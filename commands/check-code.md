# /check-code — 변경분 검사 리포트

바뀐 코드를 골라 일곱 가지를 재고 결과를 그대로 보여줍니다. 파일은 한 글자도 고치지
않고, 검사 결과로 커밋이나 다음 작업을 막지도 않습니다. 읽고 판단하는 것은 사용자 몫입니다.

**인자 없이 부르면 브랜치 전체를 잽니다.** 기준이 `main` 이라 방금 손댄 한 파일이 아니라
브랜치가 갈라진 뒤의 모든 변경이 대상입니다. 브랜치가 오래됐으면 과거 커밋에서 온 발견이
같이 나오니, 방금 고친 것만 보려면 `--base HEAD` 를 붙이십시오.

계획서 실행 흐름 (`/execute-plan`) 은 커밋 직전에 이 검사를 스스로 돌립니다. 이 커맨드는
계획서 없이 손으로 고친 뒤에 재볼 때 씁니다.

## 1. 게이트 위치 찾기

플러그인 캐시에서 먼저 찾고, 없으면 현재 저장소의 `scripts/code_gate.py` 로 떨어집니다.

```bash
G=$(find "$HOME/.claude/plugins/cache" -maxdepth 6 -path "*/js-super/*/scripts/code_gate.py" 2>/dev/null | sort -V | tail -1); [ -f "$G" ] || G=scripts/code_gate.py; if [ -f "$G" ]; then echo "$G"; else echo "GATE_ABSENT"; fi
```

출력이 `GATE_ABSENT` 이면 §2 를 실행하지 않고 아래 안내문만 냅니다. 확인하지 않고 그대로
실행하면 파이썬 오류가 사용자에게 그대로 나갑니다.

`${CLAUDE_PLUGIN_ROOT}` 는 쓰지 않습니다. 슬래시 커맨드의 Bash 환경에서 채워지지 않습니다.

## 2. 실행

가상환경을 켜지 않고 시스템 `python3` 로 돕니다. 게이트가 검사 대상 프로젝트의 가상환경을
스스로 찾기 때문입니다 (`VIRTUAL_ENV` → `.venv` → `venv` → 현재 인터프리터 순). 여기서
js-super 의 가상환경을 켜면 `VIRTUAL_ENV` 가 1순위로 잡혀 대상 프로젝트가 아닌 인터프리터로
재게 됩니다.

- 인자가 없으면 그대로 부릅니다. 기준은 게이트가 알아서 잡습니다 (`main` → `origin/HEAD` →
  `HEAD~1` 순). 손으로 고친 것을 볼 때는 브랜치 전체를 보는 쪽이 맞습니다.
- 사용자가 인자를 주면 그대로 넘깁니다. 직전 커밋 이후의 변경분만 보려면 `--base HEAD` 입니다.

```bash
python3 "$G" $ARGUMENTS
```

게이트 파일을 못 찾으면 실행하지 않고 이렇게 알립니다.

```
ℹ️ 변경분 검사 게이트를 찾지 못했습니다. js-super 플러그인이 설치돼 있는지 확인해 주세요.
```

## 3. 출력

**게이트 출력을 그대로 보여줍니다.** 다시 표를 그리거나 요약하지 않습니다. 살아남은 변이
한 줄에는 파일 · 줄 · 변이 종류 · 원본→변경 · 관련 테스트가 들어 있고, 요약하면 그것이
사라집니다.

목록이 길면 게이트가 이미 항목당 15줄에서 자르고 `... 외 N건` 을 붙입니다. 그 위에 또
자르지 않습니다. 가려진 N건을 표로 보여주는 방법은 없습니다 — 이 커맨드를 다시 돌려도 같은
15줄에서 잘립니다. 그 사실을 한 줄로 알립니다: `가려진 N건은 표에 나오지 않습니다.`

## 4. 하지 않는 것

- 파일을 고치지 않습니다. 리포트를 근거로 코드를 수정하지 않습니다.
- 검사 결과로 커밋이나 다음 작업을 막지 않습니다.
- 발견을 심각도로 재분류하거나 "이 변이는 무해합니다" 처럼 판정하지 않습니다.
- 게이트가 갖고 있지 않은 인자 (`--track` / `--mode` / `--flow` / `--stage` / `--only` /
  `--fail-under`) 를 붙이지 않습니다. 붙이면 무시되고 참고란에 찍힙니다.
