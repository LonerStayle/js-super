# H25 — /slice 슬라이스 흐름 E2E 시나리오

두 번째 실행 흐름 (`/slice`) 의 수동 검증 시나리오. 릴리즈 전 1회 사람이 돌린다.

## 준비

1. 작은 샘플 저장소 하나 (git 초기화 + 커밋 1개 이상). 테스트 러너가 이미 깔려 있어야 한다
   — 파이썬이면 pytest, Node 면 vitest / jest 중 하나. 러너가 없으면 Specifier 가 새로 깔지
   않으므로 시나리오 2번이 의미를 잃는다.
2. 게이트가 잡히는 환경인지 먼저 확인한다 —
   `find "$HOME/.claude/plugins/cache" -maxdepth 6 -path "*/js-super/*/scripts/code_gate.py"`
   가 무언가를 찍거나, 대상 저장소에 `scripts/code_gate.py` 가 있어야 한다. 둘 다 없으면
   시나리오 2~6번이 게이트 없이 돌고 시나리오 7번만 제대로 검증된다.
3. 작업 트리가 깨끗한 상태에서 시작한다. 슬라이스 끝의 커밋 하나가 무엇을 담았는지 봐야 한다.

## 실행 순서와 기대 결과

| # | 실행 | 기대 결과 |
|---|---|---|
| 1 | `/slice` (인자 없이) | 무엇을 하고 싶은지 한 줄로 묻고 턴이 끝난다. 자유 서술로 받는 자리라 `AskUserQuestion` 팝업을 띄우지 않는다 |
| 2 | `/slice "리스트 API 에 페이지 번호 인자를 받게 해줘"` | Specifier 보조 에이전트 1개 호출 → 저장소에 인수 테스트 파일이 생긴다. 테스트는 프로젝트의 기존 러너로 돌고, 새 의존성이 설치되지 않았다. `.feature` 파일이 생기지 않았다 |
| 3 | 계속 진행 | Coder 호출 → 인수 테스트가 통과한다. 이 시점까지 커밋이 하나도 생기지 않았다 (`git log` 로 확인). 요구사항 · 설계 · 계획 `.md` 가 하나도 생기지 않았다 |
| 4 | 계속 진행 | Hardener 호출 → 게이트 출력 전문이 보고에 그대로 실린다. 돈 바퀴 수가 보고에 있고 3을 넘지 않는다 |
| 5 | Step 4 팝업 | `AskUserQuestion` 으로 "커밋 / 한 번 더 / 멈춤" 을 묻는다. `CLEAN` 이어도 묻는다. 남은 발견이 있으면 게이트 출력이 팝업 전에 그대로 보인다 |
| 6 | "커밋한다" 선택 | 커밋 직전에 담기는 파일 목록과 메시지를 한 문단으로 알린다. `docs/slices/YYYY-MM.md` 에 12줄 이하 블록 하나가 붙고, 커밋 하나에 코드 · 테스트 · 노트만 담긴다 (`git show --stat` 으로 확인 — 슬라이스와 무관한 파일이 없다). 노트에 변경이력 꼬리말이 없다 |
| 7 | 게이트 파일이 없는 저장소에서 재실행 (플러그인 캐시에도 `scripts/code_gate.py` 가 없고 저장소에도 없는 상태 — `.code-gate.json` 을 지우는 것으로는 이 조건이 안 된다. 그 파일은 임계값 설정이라 없으면 게이트가 기본값으로 정상 실행된다) | Hardener 보고에 `GATE_ABSENT` 가 그대로 실리고 상태값이 `REMAINING` 이다. 슬라이스가 `CLEAN` 으로 적히지 않는다. Step 4 팝업에 "커밋한다" 선택지가 **있다** — 인수 테스트가 통과했는데 검사를 못 돌렸다는 이유로 커밋을 막지 않는다 |
| 8 | 일부러 크게: `/slice "결제 · 정산 · 환불을 다 만들어줘"` | Specifier 가 `TOO_BIG` 을 반환하고 2~4조각 분할안이 `AskUserQuestion` 으로 온다. 인수 테스트 파일이 생기지 않았다 |
| 9 | 모호하게: `/slice "코드 좀 정리해줘"` | Specifier 가 `UNCLEAR` 를 반환하고 흐름이 멈춘다. 소크라테스 대화로 넘어가지 않는다 |
| 10 | 인수 테스트를 일부러 깨고 다시 `/slice` 진행 | Hardener 가 `BLOCKED` 을 반환하고, Step 4 팝업에 "커밋한다" 선택지가 없다 |
| 10-2 | 인수 테스트를 통과시킬 수 없게 만든 뒤 (예: 필요한 외부 자원이 없는 요청) | Coder 가 `BLOCKED` 을 반환하고 Hardener 를 건너뛴다. Step 4 팝업의 재시도 선택지가 "Step 2 부터 다시 돈다" 이고 Coder 보고가 그대로 보인다. 두 번 재시도한 뒤에는 "커밋하지 않고 멈춘다" 만 남는다 |
| 11 | 슬라이스 3개를 채운 뒤 | 세 번째 슬라이스 끝에 아키텍처 정리 권유 팝업이 온다. "지금 본다" 를 골라도 코드가 바뀌지 않는다 (질문 셋의 답만 보인다) |
| 12 | 전체 세션 뒤 `git diff` | `skills/` · `scripts/` · 6 manifest 가 하나도 안 바뀌었다. 기존 흐름의 스킬이 한 번도 호출되지 않았다 |

## 실패 기록

발견한 어긋남은 이 파일 하단에 날짜와 함께 남기고, 수정 커밋과 연결한다.
