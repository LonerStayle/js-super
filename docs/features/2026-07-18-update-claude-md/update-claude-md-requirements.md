# 요구사항: /update-claude-md 커맨드

> **다음 단계 안내**: 이 문서는 PRD (기획 단계 요구사항만) 입니다. 다음 단계로 `tech-design` skill (또는 `/tech-design` 슬래시) 을 호출해서 `update-claude-md-tech-design.md` (기술 설계서) 를 만드세요. 기술 결정이나 구현 세부사항은 여기 박지 마세요.

## 1. 배경/목적

`CLAUDE.md` 안에는 두 종류의 내용이 섞여 있다.

- **프로젝트마다 달라지는 구체값** — 파일/폴더 경로, 폴더·파일 구조, 포트 번호, 파일명, 함수명, 클래스명 등
- **프로젝트가 바뀌어도 그대로 둬야 하는 본문 규약** — 워크플로우 룰, 톤 규칙, 안전성 원칙, 버전 태그, 결합 메모 같은 문서의 규약 본문

코드나 구조가 바뀌면 앞쪽 구체값이 낡는다 (예: 백엔드 로컬 포트가 `CLAUDE.md` 에는 8000 으로 적혀 있는데 실제 프로젝트는 8444 를 쓰는 상황). 이 커맨드는 **낡은 구체값만 실제 프로젝트에 맞게 갱신하고, 본문 규약은 절대 건드리지 않는** 것을 목적으로 한다.

핵심 난제는 "이건 갈아끼울 구체값" vs "이건 손대면 안 되는 본문" 을 안전하게 가려내는 판별이다. 잘못 건드리면 룰이 깨지므로, 애매하면 자동 변경하지 않고 사용자에게 확인한다.

## 2. 사용자 스토리 / 시나리오

- **누가**: js-super 워크플로우를 쓰는 개발자
- **무엇을**: 코드/구조가 바뀌어 `CLAUDE.md` 의 경로·포트·파일명·함수명·클래스명이 실제와 어긋났을 때, 룰 본문은 그대로 둔 채 구체값만 실제에 맞게 맞추고 싶다
- **왜**: `CLAUDE.md` 가 다시 정확해져서, 에이전트가 낡은 값(잘못된 포트/없는 경로)을 참조하지 않게 하려고

## 3. 기능 요구사항 (FR)

- **FR-1**: 명시 슬래시 호출 전용 (`/update-claude-md`). 자동 발동 X. (`new-skill` / `remove-skill` 빌더 패턴 답습 — instruction-only command)
- **FR-2**: 대상 `CLAUDE.md` 탐색 — 현재 프로젝트 루트부터 하위 폴더까지 존재하는 `CLAUDE.md` 파일들을 찾는다.
- **FR-3**: 대상이 하나도 없으면 **새로 만들지 않고** 안내 후 중단한다 (update-only, create 절대 X).
- **FR-4**: 대상 후보를 목록으로 보여주고, 어느 파일(들)을 업데이트할지 **`AskUserQuestion` 도구로** 사용자에게 물어본다. (단일 후보여도 확인)
- **FR-5**: 선택된 각 `CLAUDE.md` 에서 구체값(경로 / 폴더·파일 구조 / 포트 / 파일명 / 함수명 / 클래스명)을 추출한다.
- **FR-6**: 실제 프로젝트를 스캔해서 각 구체값을 검증한다 — 경로/파일이 실제로 존재하는지, 포트 설정이 실제로 무엇인지 대조해 **어긋난 항목만** 추린다.
- **FR-7**: 사용자가 직접 알려준 값(예: "포트는 8444 로")도 함께 반영한다.
- **FR-8**: 어긋난 항목을 **변경 전 / 변경 후 형태로 보여주고, 사용자 승인 후에만** 반영한다. 승인 없이 자동 반영 X.
- **FR-9**: 본문 규약(워크플로우 룰 / 톤 규칙 / 안전성 원칙 / 버전 태그 / 결합 메모 / 룰 설명 산문 등)은 **절대 수정하지 않는다.** 구체값만 교체한다.
- **FR-10**: 구체값인지 본문 규약인지 **모호한 항목은 자동 변경하지 않고** 사용자에게 확인한다.
- **FR-11**: CLAUDE.md 를 변경하기 **직전에 기존 파일 전체를 타임스탬프를 붙여 히스토리로 보관**한다. 매 갱신마다 구버전이 덮어써지지 않고 **누적**된다. (구버전 열람 용도)
- **FR-12**: 히스토리 파일은 **git 커밋 대상에서 제외**하고 로컬에만 보관한다 (`.gitignore` 처리).

## 4. 비기능 요구사항 (NFR)

- **안전성**: 본문 규약 보존이 최우선. 승인 없는 자동 반영 금지. 모호하면 건드리지 않기.
- **탐지 방식**: 자동 스캔 + 사용자 확인 (Read / Grep / Glob / Bash 탐색 도구 사용). 스캔으로 실제 값을 찾되, 반영은 항상 사용자 승인 게이트를 거친다.
- **안내 톤**: 한국어 친화 (짧은 문장, 완전 문장 보고, 마커 다발 금지 — CLAUDE.md A-1~A-5).

## 5. 범위 밖 (Out of Scope)

- 존재하지 않는 `CLAUDE.md` 를 새로 생성하기 (절대 X — FR-3)
- 본문 규약(룰 / 톤 / 원칙 / 워크플로우 설명)의 재작성·개선·리팩터
- 현재 프로젝트 밖의 `CLAUDE.md` (다른 프로젝트) 조회·수정
- 글로벌 개인 설정 `~/.claude/CLAUDE.md` 수정 (사용자 개인 지침이라 대상 제외)
- `AGENTS.md` / `GEMINI.md` 등 다른 규약 파일 (이번 범위는 `CLAUDE.md` 한정)
- **자동 복원(restore) 기능** — 히스토리는 열람 용도. 구버전으로 되돌리는 것은 사용자가 수동으로 처리 (커맨드는 복원 명령을 제공하지 않음)

## 6. 수용 기준 (Acceptance Criteria)

- 대상 `CLAUDE.md` 가 하나도 없으면 → 새로 만들지 않고 안내 후 중단한다 (Yes/No 검증 가능)
- 대상이 여러 개면 → `AskUserQuestion` 으로 어느 파일을 업데이트할지 물어본다
- 구체값이 실제 프로젝트와 어긋나면 → 변경 전/후를 보여주고 사용자 승인 후에만 반영한다
- 본문 규약(룰/톤/버전 태그/결합 메모)은 → 커맨드 실행 후에도 그대로 유지된다 (미변경)
- 구체값/본문 판별이 모호한 항목은 → 자동 변경되지 않고 사용자 확인을 거친다
- 변경을 반영하기 직전에 → 구버전이 히스토리에 타임스탬프로 누적 보관된다 (덮어쓰기 없음)
- 히스토리 파일은 → git 커밋 대상에서 제외된다 (`.gitignore`)
