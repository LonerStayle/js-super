# 개발방향: /update-claude-md 커맨드

> **다음 단계 안내**: 이 문서는 기술 설계서입니다 (아키텍처 / 컴포넌트 / 결정 / 위험 / 테스트 전략). `update-claude-md-requirements.md` (PRD) 를 기반으로 작성됐고, 다음 단계 `update-claude-md-implementation-plan.md` (단계별 계획) 의 입력이 됩니다. 단계별 구현 task 는 여기 박지 마세요.

## 1. 아키텍처 개요

instruction-only 슬래시 커맨드 `commands/update-claude-md.md` 1 파일. 메인 에이전트가 본문 instruction 을 따라 **Read / Grep / Glob / Bash(탐색) + AskUserQuestion + Edit** 도구로 동작한다. `new-skill.md` / `remove-skill.md` 빌더 패턴 답습 — bash 스크립트나 외부 의존 없음.

실행 흐름:

```
1. 대상 탐색      현재 프로젝트 트리에서 CLAUDE.md 파일들을 Glob 으로 수집
2. 대상 0건 검사  하나도 없으면 → 안내 후 중단 (생성 절대 X, FR-3)
3. 대상 선택      후보 목록을 AskUserQuestion 으로 제시 → 업데이트할 파일 선택 (FR-4)
4. 구체값 추출    선택된 CLAUDE.md 에서 '실제와 대조 가능한 사실'만 후보로 뽑음 (FR-5)
5. 실제 대조      각 후보를 실제 프로젝트와 대조해 검증 (경로 존재? 포트 실제값?) (FR-6)
6. 불일치 산출    확인된 불일치 + 사용자가 직접 준 값만 변경 후보로 (FR-6, FR-7)
7. 승인 게이트    파일별 변경 전/후를 보여주고 AskUserQuestion 승인 (FR-8)
8. 히스토리 보관  반영 직전 구버전 전체를 히스토리 폴더에 타임스탬프로 저장(누적) + .gitignore 보장 (FR-11, FR-12)
9. 반영           승인된 항목만 Edit 로 반영 (문맥 단위, 전역 치환 X)
10. 보고          갱신/미갱신/보류(모호) 항목 + 히스토리 저장 위치를 한국어로 보고
```

### 히스토리 저장 위치

각 갱신 대상 CLAUDE.md 와 **같은 디렉토리에 `.claude-md-history/` 폴더**를 두고, 구버전을 `CLAUDE.md.<YYYYMMDDHHMMSS>` 파일명으로 누적 저장한다 (덮어쓰기 없음). 대상이 여러 개면 각 CLAUDE.md 옆에 각자의 히스토리 폴더가 생긴다. 커맨드는 프로젝트 `.gitignore` 에 `.claude-md-history/` 항목이 없으면 추가하고, 추가 사실을 사용자에게 보고한다.

## 5. 핵심 결정 + 대안 비교

### 결정 1 — 판별 방식 = 검증 기반 (채택)

- **채택**: CLAUDE.md 에서 "실제 프로젝트와 대조 가능한 사실"(경로 / 폴더·파일 구조 / 포트 / 파일명 / 함수·클래스명)만 변경 후보로 뽑고, 실제와 대조해 **확인된 불일치만** 제안한다. 룰·톤·원칙 산문은 "대조 가능한 사실"이 아니므로 애초에 후보에서 빠진다.
- **대안 A (정규식 화이트리스트)**: 경로/포트/파일명 패턴을 정규식으로만 추출. → 새 종류 값 누락 + 본문 안 비슷한 숫자/단어 오판 위험. 기각.
- **대안 B (LLM 순수 판단)**: 각 줄을 읽고 구체값/본문 판단만. → 실제 대조 없이 판단하면 오판 시 검증 장치가 없음. 기각.
- **이유**: 검증 기반은 "실제와 대조" 자체가 안전장치라 본문 규약이 구조적으로 배제된다. 사용자가 처음 강조한 우려(본문 손상)를 설계로 막는다.

### 결정 2 — instruction-only 커맨드 (채택)

- **채택**: `commands/update-claude-md.md` 본문 instruction 만. `new-skill`/`remove-skill` 패턴.
- **대안 (Python helper 스크립트)**: 검증 로직을 결정론 코드로. → CLAUDE.md 구조·프로젝트 구조가 프로젝트마다 달라 파싱이 brittle + 의존성 추가. instruction-only 가 더 유연. 기각.

### 결정 3 — 검증 신뢰도 gradient 처리 (채택)

- 경로 / 폴더구조 / 포트 / 파일명 = 실제와 대조 쉬움 (**높은 신뢰도**).
- 함수명 / 클래스명 = 코드 이해 필요 (**낮은 신뢰도**).
- **채택**: 둘 다 후보로 뽑되, 신뢰도 낮은 항목은 "확인 필요(불확실)"로 라벨링해 자동 제안하지 않고 사용자에게 판단을 넘긴다 (FR-10 실현).

### 결정 4 — 대상 파일 범위 (채택)

- **채택**: 현재 프로젝트 트리 안의 `CLAUDE.md` (루트 + 하위). `node_modules` / `.git` / `vendor` / 플러그인 cache / `.worktrees` 등 빌드·의존·격리 디렉토리는 제외.
- 글로벌 `~/.claude/CLAUDE.md` 는 제외 (범위 밖 — 사용자 개인 지침).
- **대안 (전체 glob)**: 노이즈 많음. 기각.

### 결정 5 — 승인 granularity (채택)

- **채택**: 파일별로 제안 diff 묶음을 변경 전/후로 보여주고 **파일 단위 승인** (AskUserQuestion). 사용자가 개별 항목을 빼고 싶으면 자유 응답으로 조정.
- **대안 (전체 일괄 승인)**: 위험. **대안 (항목마다 개별 게이트)**: 마찰 과다. 둘 다 기각.

### 결정 6 — 버전 히스토리 방식 (채택)

- **채택**: 변경 반영 직전에 구버전 전체를 `.claude-md-history/CLAUDE.md.<timestamp>` 로 **누적 저장**(덮어쓰기 없음). 히스토리는 **열람 용도**이고 커맨드는 **자동 복원 기능을 제공하지 않는다**(사용자 수동). 히스토리 폴더는 **git 커밋에서 제외**(`.gitignore`).
- **대안 A (최신 백업 1개만)**: 매번 직전 버전만 남김. → 사용자가 "구버전 열람"을 원해 기각 (여러 시점 필요).
- **대안 B (복원 명령 포함)**: `--restore` 로 되돌리기 제공. → 사용자가 "복원은 수동, 열람 목적"이라 불필요하다고 명시. 범위 밖으로 기각.
- **대안 C (히스토리 git 커밋)**: 히스토리를 저장소에 커밋. → 사용자가 커밋 제외 요청. 기각.
- **이유**: "구버전이 궁금해서 보는 용도"라는 사용자 의도에 맞춰 누적 열람만 지원하고 나머지는 덜어냄 (YAGNI).

## 6. 위험/사이드이펙트 (preliminary)

- **R1 (breaking)**: 본문 규약을 구체값으로 오판 → 룰 손상. **완화**: 검증 기반 후보 배제 + 확인된 불일치만 + 모호하면 자동 변경 X + 항상 승인 게이트.
- **R2 (side-effect)**: 실제 프로젝트 스캔 오탐 (예: 포트가 여러 개) → 잘못된 "실제값" 추론. **완화**: 제안 시 근거(어디서 찾았는지)를 함께 표시 + 사용자 승인.
- **R3 (side-effect)**: 같은 문자열이 구체값과 본문 양쪽에 등장 (예: "8000"이 포트로도, 설명 예시로도) → 전역 치환 시 본문 오염. **완화**: 문맥 단위 개별 제안 (전역 `replace_all` 금지), 줄/맥락 표시.
- **R4 (side-effect)**: 여러 CLAUDE.md 중 일부만 갱신 → 파일 간 불일치. **완화**: 대상 선택을 사용자에게 위임 (FR-4) + 보고에 갱신/미갱신 명시.
- **R5 (side-effect)**: 히스토리가 갱신마다 쌓여 디스크·폴더가 누적됨. **완화**: 커맨드는 자동 정리하지 않음(누적이 사용자 의도) + 히스토리 폴더 위치를 보고해 사용자가 수동 정리 가능. gitignore 처리로 저장소 오염은 방지.

| T-9 히스토리 gitignore | 갱신 실행 | `.gitignore` 에 `.claude-md-history/` 항목 존재 + 보고 |

T-1 / T-3 / T-4 / T-7 = critical. T-5 / T-6 / T-8 / T-9 = edge case.
