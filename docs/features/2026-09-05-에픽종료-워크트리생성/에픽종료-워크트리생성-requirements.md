# 요구사항: 에픽 종료 워크트리 생성

> **다음 단계 안내**: 이 문서는 요구사항 (기획 단계) 입니다. 다음 단계로 `tech-design` skill (또는 `/design-tech` 슬래시) 을 호출해서 `<slug>-tech-design.md` (기술 설계서) 를 만드세요. 기술 결정이나 구현 세부사항은 여기 박지 마세요 — 그건 다음 산출물 (tech-design, 3개 트랙이면 plan 까지) 에 들어갑니다.

## 배경

에픽 단위 브레인스토밍은 큰 작업 하나를 여러 파트로 나눠 진행하고, 파트 사이의 맥락을 세 파일로 나른다. 큰 그림, 이월 노트, 예상도다. 그 설계는 "마무리 단계에서 다음 파트의 부모 워크트리를 안내한다" 까지를 범위로 정했다. 워크트리를 만드는 일은 사용자가 직접 하기로 했다.

이 안내는 실제 사용에서 한 번도 나타나지 않았다. 원인은 둘이다.

| 원인 | 내용 |
|---|---|
| 구현 시 잘림 | 브레인스토밍 스킬에 넣을 섹션의 뒷부분이 복사 중에 잘렸다. 예시 코드 블록이 섹션 블록 안에 겹쳐 있어서 안쪽 블록의 끝을 섹션의 끝으로 읽었다. 워크트리 안내와 관련 스킬 헤더가 파일에 없다 |
| 위치 어긋남 | 에픽 요구사항서의 진행 흐름은 마무리를 실행 뒤에 그렸는데, 구현은 요구사항 승인 직후에 놓았다 |

그리고 안내만으로는 부족하다. 사용자가 원하는 것은 다음 파트의 워크트리가 실제로 만들어지고, 그 워크트리에서 연 새 세션이 앞 파트의 맥락을 넘겨받아 곧바로 브레인스토밍을 시작하는 것이다. 이 문서는 그 흐름을 정한다.

## 파트 사슬

큰 작업은 파트의 사슬이다. 에픽 워크트리가 첫 파트이고, 그 다음 파트는 앞 파트의 마지막 커밋에서 갈라진다.

```
결제                          에픽 워크트리 (첫 파트)
 └─ 결제__ep_part2_환불        첫 파트의 마지막 커밋에서 갈라짐
      └─ 결제__ep_part3_정산    part2 의 마지막 커밋에서 갈라짐
           └─ 결제__ep_part4_리포트
```

사슬은 앞으로만 간다. 각 파트는 앞 파트의 코드와 문서와 에픽 파일을 전부 물려받는다. 되돌아가서 합치는 일은 없다. 각 파트의 브랜치는 그 시점의 스냅숏으로 남는다.

형제 파트를 동시에 만들지 않는다. 마무리 단계는 항상 다음 파트 하나만 만든다. 병렬로 실험하고 싶으면 원하는 자식 세션에서 다시 다음 자식을 갈라내면 된다. 형제를 만들지 않으므로 큰 그림 파일이 두 갈래로 갈리는 일도 없다.

| 자리 | 워크트리 이름 |
|---|---|
| 에픽 워크트리 (첫 파트) | 사용자가 만든 이름 그대로. 예: `결제` |
| 두 번째 이후 파트 | `<에픽 워크트리 이름>__ep_part<번호>_<작업명>`. 번호는 앞 파트 번호에 1 을 더한다. 첫 파트가 1 이므로 두 번째는 2 |
| 사용자가 이름을 직접 준 경우 | 그대로 쓴다. 규칙으로 덮어씌우지 않는다 |

작업명은 다음 파트의 주제에서 짓는다. 이름은 에픽 워크트리 이름과 파트 번호만 갖고, 앞 파트 이름을 누적하지 않는다. 사슬의 순서는 번호로 보이고, 어느 파트에서 갈라졌는지는 워크트리를 만들 때 남는 부모 기록이 갖고 있다.

## 마무리가 일어나는 시점

실행이 끝난 뒤다. 구현계획 실행이 끝나고 커밋까지 마친 시점이다. 브레인스토밍 스킬에 있던 마무리 단계 (큰 그림 갱신 판정, 이월 항목 기록, 예상 빗나감 판정) 는 이 자리로 통째로 옮긴다. 브레인스토밍에는 시작 단계 (에픽 파일 읽기) 와 소속 표식만 남는다.

| 후보 시점 | 채택 | 이유 |
|---|---|---|
| 실행 완료 뒤 | 채택 | 자식은 부모의 마지막 커밋에서 갈라지므로 이때 갈라내야 앞 파트의 코드를 물려받는다. 미룬 항목은 실행 중에 가장 많이 나온다. 에픽 요구사항서의 진행 흐름 그림과 일치한다 |
| 요구사항 승인 직후 | 버림 | 지금 자리다. 다음 파트가 앞 파트의 코드 없이 시작한다. 실행 중 나온 미룬 항목이 이월 노트에 안 남는다 |
| 구현계획서 작성 직후 | 버림 | 설계는 보이지만 코드는 없다. 위와 같은 문제 |

2개 문서 트랙에서도 같은 시점에 일어나야 한다. 기술설계까지만 확정하고 구현계획서 없이 바로 실행하는 피처가 그 경우다. 어느 트랙이든 "실행이 끝났다" 는 시점은 하나이고, 마무리는 그 시점에 붙는다. 실행 방식 (메인이 직접 하는 인라인, 보조 에이전트가 하는 웨이브) 도 가리지 않는다.

## 마무리 순서

```
실행 완료 (커밋까지 끝남)
  │
  ▼
① 에픽 파일 갱신
  │   큰 그림 갱신 판정 · 이월 항목 기록 · 예상 빗나감 판정
  ▼
② 커밋
  │   갱신된 에픽 파일을 커밋한다
  ▼
③ 다음 파트 선택
  │   갱신된 큰 그림의 착수 가능 목록에서 하나
  ▼
④ 워크트리 생성
  │   이름 규칙대로, 현재 워크트리의 마지막 커밋에서
  ▼
⑤ 안내
  │   새 세션 열기 · 세션 이름 짓기 · 자식 커맨드 실행
  ▼
⑥ 인수인계
      자식이 인사하면 부모가 인수인계를 보낸다
```

| 번호 | 하는 일 | 지켜야 할 것 |
|---|---|---|
| ① | 에픽 기능이 정한 갱신 규칙 그대로. 바뀐 것이 없으면 파일을 건드리지 않는다 | 갱신 판정 기준은 에픽 기능의 것을 바꾸지 않는다 |
| ② | 갱신된 에픽 파일을 커밋한다 | 자식이 최신 큰 그림을 물려받는 유일한 경로다. 커밋 전에 갈라내면 옛 큰 그림을 물려받는다 |
| ③ | 착수 가능 목록을 보여주고 추천을 먼저 말한 뒤 사용자가 고른다. "지금은 안 만듦" 과 "에픽 완료" 도 고를 수 있다 | 항상 하나만 고른다. 예상도는 읽지 않는다 |
| ④ | 기존 워크트리 생성 절차를 쓴다. 부모 기록도 그 절차가 남긴다 | 이름 규칙은 위 표. git 이 추적하지 않는 문서 파일은 직접 복사한다 |
| ⑤ | 워크트리 경로, 새 터미널에서 세션 열기, 세션 이름에 워크트리 이름 넣기, 자식 커맨드 실행. 이 넷을 안내한다 | 부모는 새 세션을 띄울 수 없다. 사용자가 연다 |
| ⑥ | 부모 세션은 턴을 마치고 기다린다. 자식의 인사가 오면 인수인계를 보낸다 | 인사가 오기 전에는 아무것도 보내지 않는다 |

## 세션 인수인계

새 워크트리에서 연 세션이 앞 파트의 맥락을 받는 방법이다.

```
부모 세션                              자식 세션
  │ ⑤ 안내 후 기다림                       │ 사용자가 새 터미널에서 열고 이름을 지음
  │                                     │ 사용자가 자식 커맨드를 실행
  │ ◄── 인사 "나 떴어, 이름은 X" ──────────┤
  │ 인수인계 작성                           │
  │ ── 인수인계 전문 ─────────────────────► │ 받아서 곧바로 브레인스토밍 시작
```

| 역할 | 하는 일 |
|---|---|
| 자식 커맨드 | 명시 호출 전용 슬래시 커맨드. 부모 세션을 찾아 인사를 보낸다. 부모 세션은 워크트리를 만들 때 남은 부모 브랜치 기록과 세션 이름으로 찾는다. 못 찾으면 사용자에게 알린다 |
| 부모 세션 | 인사를 받으면 인수인계 메시지를 자식에게 보낸다 |
| 자식 세션 | 인수인계를 받으면 추가 질문 없이 브레인스토밍을 시작한다. 시작 단계가 에픽 파일을 읽는다 |

자식이 부모를 찾으려면 세션 이름에 워크트리 이름이 들어 있어야 한다. 부모는 안내 단계에서 이 관례를 알리고, 자기 세션 이름이 관례에 맞는지도 확인한다. 맞지 않으면 사용자에게 이름을 바꾸도록 안내한다.

| 자식 → 부모 인사 방식 | 채택 | 이유 |
|---|---|---|
| 자식이 먼저 인사 | 채택 | 부모는 자식이 언제 뜨는지 모른다. 자식이 뜬 시점을 자식이 가장 잘 안다. 사용자는 새 세션을 열고 이름을 지은 뒤 커맨드 하나만 친다 |
| 사용자가 부모에게 알림 | 버림 | 사용자가 두 세션을 오가야 한다 |
| 부모가 이름 규칙으로 추정 | 버림 | 자식이 언제 뜨는지 부모가 모르므로 결국 사용자가 부모에게 "보내" 라고 해야 한다 |

인수인계 메시지에는 파일에 없는 것만 담는다.

| 담는 것 | 이유 |
|---|---|
| 다음 파트의 주제와 그것을 고른 이유 | 마무리 단계에서 정한 것이라 어느 파일에도 없다 |
| 이번 파트에서 정한 것, 버린 안, 실행하면서 알게 된 함정 | 피처 문서에 흩어져 있거나 대화에만 있다. 다음 파트가 같은 논의를 되풀이하지 않게 한다 |
| 읽을 파일의 경로 | 에픽 파일 셋과 방금 끝낸 파트의 피처 폴더. 자식 워크트리에 이미 있으므로 경로만 |
| 부모 브랜치 이름 | 어디서 갈라졌는지 |

에픽 파일의 내용은 복사하지 않는다. 파일이 정본이고, 자식 워크트리에 이미 있으며, 브레인스토밍 시작 단계가 그 파일을 읽는다. 메시지에 복사하면 형상관리 밖의 사본이 하나 더 생기고, 에픽이 바뀔수록 그 사본은 빨리 낡는다. 예상도는 어떤 형태로도 넣지 않는다. 다음 주제를 고를 때 예상도를 읽지 않는다는 에픽 기능의 원칙 때문이다.

자식이 부모를 찾지 못하거나 부모가 답하지 않으면 자식은 사용자에게 그 사실을 알리고, 사용자가 원하면 인수인계 없이 브레인스토밍을 시작할 수 있다. 에픽 파일은 워크트리에 있으므로 시작 단계가 큰 그림과 이월 노트를 읽는다.

## git 이 추적하지 않는 문서

협업 프로젝트에서는 에픽 폴더를, 때로는 피처 문서 폴더까지 gitignore 에 넣는 경우가 있다. 그러면 자식 워크트리는 그 파일을 커밋으로 물려받지 못한다.

인수인계에서 읽으라고 지정하는 파일 중 git 이 추적하지 않는 것은 워크트리를 만들 때 부모가 자식 워크트리에 직접 복사한다. 부모에서 자식으로 한 방향만이다. 사슬이 앞으로만 가므로 되돌려 복사하는 경우는 없다.

## 단발성 브레인스토밍에는 붙지 않는다

이 기능은 에픽이 진행 중일 때만 붙는다. 진행 중인 큰 작업이 없거나 이번 피처의 요구사항 문서에 소속 표식이 없으면, 실행 끝에 아무 출력도 추가되지 않는다. 안내 문구도 없다. 에픽 없이 피처 하나만 만드는 기존 사용법은 지금과 똑같이 동작해야 한다.

## 요구 항목

### 발동

**요구 1**: 진행 중인 큰 작업이 있고 이번 피처의 요구사항 문서에 소속 표식이 있을 때만 마무리 단계가 발동한다. 둘 중 하나라도 없으면 아무 출력 없이 지나간다.

**요구 2**: 마무리 단계는 실행이 끝나고 커밋까지 마친 시점에 발동한다. 구현계획서 없이 기술설계에서 바로 실행하는 2개 문서 트랙에서도, 메인이 직접 하는 인라인 실행과 보조 에이전트가 하는 웨이브 실행 어느 쪽에서도 같은 시점에 발동한다.

**요구 3**: 브레인스토밍 스킬에 있던 마무리 단계 (큰 그림 갱신 판정, 이월 항목 기록, 예상 빗나감 판정) 는 실행 끝으로 옮긴다. 브레인스토밍에는 시작 단계와 소속 표식만 남는다.

### 마무리 순서

**요구 4**: 에픽 파일을 갱신하고 커밋한 뒤에 다음 파트의 워크트리를 만든다. 커밋 전에 갈라내지 않는다.

**요구 5**: 다음 파트는 갱신된 큰 그림의 착수 가능 목록에서 고른다. 추천을 먼저 말하고 사용자가 확인한다. 항상 하나만 고르며, "지금은 안 만듦" 과 "에픽 완료" 도 고를 수 있다. 예상도는 읽지 않는다.

**요구 6**: 두 번째 이후 파트의 워크트리 이름은 `<에픽 워크트리 이름>__ep_part<번호>_<작업명>` 이다. 번호는 앞 파트 번호에 1 을 더하고, 앞 파트 이름을 누적하지 않는다. 사용자가 이름을 직접 주면 그대로 쓴다.

**요구 7**: 워크트리는 현재 워크트리의 마지막 커밋에서 갈라내며, 기존 워크트리 생성 절차와 부모 기록을 그대로 쓴다.

**요구 8**: 인수인계에서 읽으라고 지정하는 파일 중 git 이 추적하지 않는 것은 워크트리를 만들 때 부모가 자식 워크트리에 직접 복사한다. 부모에서 자식으로 한 방향만이다.

**요구 9**: 워크트리를 만든 뒤 사용자에게 워크트리 경로, 새 터미널에서 세션 열기, 세션 이름에 워크트리 이름 넣기, 자식 커맨드 실행을 안내한다. 부모는 자기 세션 이름이 관례에 맞는지 확인하고 맞지 않으면 바꾸도록 안내한다.

### 세션 인수인계

**요구 10**: 자식 커맨드는 명시 호출 전용 슬래시 커맨드다. 부모 브랜치 기록과 세션 이름으로 부모 세션을 찾아 인사를 보낸다. 못 찾으면 사용자에게 알린다.

**요구 11**: 부모 세션은 자식의 인사를 받으면 인수인계 메시지를 보낸다. 내용은 다음 파트의 주제와 이유, 이번 파트의 결정과 버린 안과 함정, 읽을 파일의 경로, 부모 브랜치 이름이다. 에픽 파일의 내용은 복사하지 않고 예상도는 어떤 형태로도 넣지 않는다.

**요구 12**: 자식 세션은 인수인계를 받으면 추가 질문 없이 브레인스토밍을 시작한다.

**요구 13**: 자식이 부모를 찾지 못하거나 부모가 답하지 않으면 사용자에게 알리고, 사용자가 원하면 인수인계 없이 브레인스토밍을 시작할 수 있다.

### 보존

**요구 14**: 진행 중인 큰 작업이 없는 단발성 브레인스토밍과 실행은 지금과 똑같이 동작한다. 실행 끝에 어떤 출력도 추가되지 않는다.

**요구 15**: 사슬은 앞으로만 간다. 되돌려 합치는 단계와 형제 파트 동시 생성은 없다.

**요구 16**: 브레인스토밍 스킬에서 잘려 나간 부분을 정리한다. 관련 스킬 헤더를 복구하고, 옮겨 간 마무리 단계와 그 흐름도 노드를 브레인스토밍에서 뺀다.

## 범위 밖

| 항목 | 이유 |
|---|---|
| 부모가 새 세션을 띄우는 것 | 세션은 사용자가 터미널에서 연다 |
| 형제 워크트리 동시 생성 | 항상 하나. 병렬 실험은 사용자가 자식 세션에서 다시 갈라낸다 |
| 되돌려 합치기 | 사슬은 앞으로만 |
| 에픽 파일 내용을 메시지에 복사 | 파일이 정본. 경로만 보낸다 |
| 예상도를 인수인계에 넣는 것 | 다음 주제가 예상을 따라가게 된다 |
| 큰 그림 파일을 붙이기 형식으로 바꾸는 것 | 에픽 파일 형식 변경은 별도 작업 |
| 자동 브레인스토밍 (auto-brainstorming) | 소속 표식을 남기지 않으므로 그 피처에는 마무리가 붙지 않는다. 정식 브레인스토밍으로 표식이 붙은 피처를 자동 실행 커맨드로 실행한 경우는 요구 2 대로 마무리가 발동한다 |
| 다른 기기의 세션에 보내는 것 | 같은 기기의 세션만 |

## 성공 기준

| 번호 | 기준 |
|---|---|
| 1 | 앞 파트의 실행이 끝나면 에픽 파일이 갱신되고 커밋된 뒤 워크트리가 만들어지고, 새 세션을 열어 이름을 짓고 자식 커맨드를 실행하라는 안내가 나온다 |
| 2 | 자식 세션에서 그 커맨드를 치면 부모에게 인사가 가고, 부모가 인수인계를 보내고, 자식은 추가 질문 없이 다음 파트 브레인스토밍을 시작한다 |
| 3 | 2개 문서 트랙에서도 기준 1 이 똑같이 일어난다 |
| 4 | 에픽 폴더가 gitignore 여도 자식 워크트리에 에픽 파일 셋이 들어 있다 |
| 5 | 에픽이 없는 프로젝트에서는 실행 끝에 아무 출력도 추가되지 않는다 |

## 제약

| 제약 | 내용 |
|---|---|
| 세션 찾기 | 자식이 부모 세션을 찾으려면 부모 브랜치 이름을 알아야 한다. 워크트리를 만들 때 남는 부모 기록을 쓴다. 세션 이름에 워크트리 이름이 들어 있어야 한다 |
| 실행 끝 지점이 셋 | 인라인 실행, 보조 에이전트 실행, 2개 문서 트랙. 세 곳 모두에서 같은 마무리가 돌아야 한다 |
