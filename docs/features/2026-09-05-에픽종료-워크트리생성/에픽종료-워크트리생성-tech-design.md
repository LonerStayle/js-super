# 개발방향: 에픽 종료 워크트리 생성

> **다음 단계 안내**: 이 문서는 기술 설계서입니다 (아키텍처 / 컴포넌트 / 데이터 / 인터페이스 / 결정 / 위험 / 테스트 전략). `<slug>-requirements.md` 를 기반으로 작성됩니다. 3개 트랙이면 다음 단계 `<slug>-implementation-plan.md` (단계별 계획) 의 입력이 됩니다 (`writing-plans` skill 또는 `/write-plan` 슬래시). 2개 확정 트랙 (frontmatter `depth: 2`) 이면 이 문서가 마지막 산출물입니다. 단계별 구현 task 는 여기 박지 마세요 — 그건 다음 산출물 (plan) 에 들어갑니다.

## 1. 아키텍처 개요

마무리 절차는 새 스킬 하나에 모으고, 실행이 끝나는 자리 셋이 그 스킬을 부른다. 자식 쪽은 커맨드 하나다.

```
┌─ 부모 세션 (part N 워크트리) ──────────────────────────────────────────────┐
│                                                                            │
│  실행이 끝나는 자리                                                          │
│  ┌──────────────┐ ┌──────────────────┐ ┌────────────────────┐              │
│  │ ① 인라인 실행  │ │ ② 보조 에이전트 실행 │ │ ③ 2개 문서 트랙      │              │
│  │ executing-    │ │ js-super-sub-    │ │ (자동 신호 없음)     │              │
│  │ plans         │ │ driven           │ │                    │              │
│  └──────┬───────┘ └────────┬─────────┘ └─────────┬──────────┘              │
│         │ 기존 호출          │ 기존 호출             │ 사용자가 /epic-next     │
│         ▼                  ▼                    │                         │
│  ┌──────────────────────────────┐               │                         │
│  │ ④ finishing-a-development-   │               │                         │
│  │    branch (테스트 + 종료 메시지) │               │                         │
│  └──────────────┬───────────────┘               │                         │
│                 │ 끝에서 invoke                    │ invoke                  │
│                 ▼                                ▼                         │
│  ┌────────────────────────────────────────────────────────────┐            │
│  │ ⑤ epic-close 스킬                                           │            │
│  │    에픽 없음 → 조용히 종료                                     │            │
│  │    에픽 파일 갱신 → 커밋 → 다음 파트 선택 → 워크트리 생성 → 안내   │            │
│  │    ┌ 이름·미추적 경로 계산: ⑥ scripts/epic_chain.py           │            │
│  │    └ 워크트리 생성: ⑦ setting-up-worktrees (기존)              │            │
│  └────────────────────────────────────────────────────────────┘            │
│                 │ 턴 종료, 인사 대기                                          │
└─────────────────┼──────────────────────────────────────────────────────────┘
                  │                    ⑧ 세션 간 메시지
                  │  ◄── 인사 ──────────────────────────┐
                  │  ── 인수인계 ──────────────────────► │
┌─────────────────┼──────────────────────────────────────┼───────────────────┐
│ 자식 세션 (part N+1 워크트리)                            │                   │
│                                                        │                   │
│   사용자: 새 터미널 → 세션 열기 → 이름 짓기 → /epic-handoff  │                   │
│   ┌──────────────────────────┐                         │                   │
│   │ ⑨ /epic-handoff 커맨드     │ ── 부모 찾기 · 인사 ──────┘                   │
│   │    인수인계 도착 → invoke    │                                             │
│   └────────────┬─────────────┘                                             │
│                ▼                                                           │
│   ┌──────────────────────────┐                                             │
│   │ ⑩ brainstorming 스킬       │  시작 단계가 에픽 파일을 읽는다 (기존)             │
│   │    마무리 단계는 이제 없음    │                                             │
│   └──────────────────────────┘                                             │
└────────────────────────────────────────────────────────────────────────────┘
```

| 번호 | 구성 요소 | 역할 |
|---|---|---|
| ① | 인라인 실행 스킬 | 마지막 단계에서 이미 ④ 를 부른다. 변경 없음 |
| ② | 보조 에이전트 실행 스킬 | 마지막 단계에서 이미 ④ 를 부른다. 변경 없음 |
| ③ | 2개 문서 트랙 | 실행이 스킬 밖에서 일어나므로 끝났다는 신호가 없다. 사용자가 `/epic-next` 를 친다. 기술설계 스킬의 2개 확정 종료 안내에 이 한 줄을 붙인다 |
| ④ | 마무리 스킬 | 테스트와 종료 메시지 뒤에 ⑤ 를 한 줄로 부른다. 에픽이 없으면 ⑤ 가 조용히 돌아온다 |
| ⑤ | 새 스킬 epic-close | 마무리 절차 전체. 브레인스토밍에 있던 세 판정을 여기로 옮긴다 |
| ⑥ | 새 스크립트 | 브랜치 이름에서 에픽 이름과 파트 번호를 읽고, 다음 이름을 만들고, git 이 추적하지 않는 경로를 가려내고, 소속 피처 중 최근 수정 폴더를 고른다. 표준 라이브러리만 |
| ⑦ | 워크트리 생성 스킬 | 그대로 쓴다. 부모 기록과 환경 파일 복사와 메모리 심링크가 여기서 나온다 |
| ⑧ | 세션 간 메시지 | 같은 기기의 세션끼리 이름으로 보낸다. 인사와 인수인계 두 종류 |
| ⑨ | 새 커맨드 /epic-handoff | 부모를 찾아 인사하고, 인수인계가 오면 ⑩ 을 부른다 |
| ⑩ | 브레인스토밍 스킬 | 마무리 단계와 그 흐름도 노드를 뺀다. 잘린 부분을 정리한다 |

epic-close (⑤) 안의 단계는 이름으로 부른다. 도면의 원문자 번호와 겹치지 않게 하기 위해서다.

| 단계 | 하는 일 |
|---|---|
| 이번 파트 판별 | 어느 피처가 방금 끝난 파트인지 정한다 (§3) |
| 발동 검사 | 진행 중 에픽과 소속 표식이 없으면 아무 출력 없이 돌아간다 |
| 갱신 | 큰 그림 갱신 판정 · 이월 항목 기록 · 예상 빗나감 판정. 브레인스토밍에 있던 규칙 그대로 |
| 갱신 커밋 | 에픽 폴더의 파일만 명시해 커밋한다 |
| 선택 | 다음 파트를 고른다 (§3). 안 만듦 · 에픽 완료 갈래는 여기서 끝난다 |
| 생성 | 이름을 확정하고 워크트리 생성 스킬을 부른 뒤 미추적 문서를 복사한다 |
| 안내 | 새 세션 열기 · 이름 관례 · 자식 커맨드 실행을 안내하고 자기 세션 이름을 확인한다 |
| 인사 대기 | 턴을 마친다. 자식의 인사가 오면 인수인계를 보낸다 |

## 3. 데이터 형식

새 저장소나 스키마는 없다. 이름 규칙과 메시지 형식이 이 기능의 데이터다.

### 이번 파트 판별

| 경우 | 판정 |
|---|---|
| 호출 인자로 피처 폴더가 왔을 때 | 그 폴더 |
| 인자가 없을 때 | 진행 중 에픽의 소속 피처 (요구사항 문서에 소속 표식이 있는 것) 중 파일이 가장 최근에 수정된 폴더. 어느 폴더를 골랐는지 한 줄 알린다 |
| 소속 피처가 하나도 없을 때 | 발동 조건 미달. 아무 출력 없이 돌아간다 |

에픽 스캔 스크립트가 진행 중 에픽과 소속 피처 목록을 준다. 최근 수정 판정만 새 스크립트가 한다.

### 다음 파트 선택

입력은 갱신이 끝난 큰 그림의 "지금 착수 가능" 목록이다. 예상도는 열지 않는다. 모델이 그중 하나를 추천하고 이유를 먼저 말한 뒤 `AskUserQuestion` 으로 고르게 한다.

| 선택지 | 그 뒤 |
|---|---|
| 추천 파트 (첫 번째 옵션) | 생성 단계로 |
| 착수 가능 목록의 다른 항목 | 생성 단계로 |
| 지금은 안 만듦 | "나중에 `/epic-next` 로 이어갈 수 있습니다" 한 줄을 내고 끝난다. 갱신 커밋은 이미 끝났으므로 되돌리지 않는다 |
| 에픽 완료 | 큰 그림의 상태 줄을 `완료` 로 바꾸고 커밋한 뒤 끝난다. `/epic done` 과 같은 동작 |

파트를 골랐으면 이름을 확정한다. 규칙대로 만든 이름을 보여주고 `AskUserQuestion` 으로 "이 이름으로" 또는 직접 입력 (Other) 을 받는다. 직접 입력한 이름은 그대로 쓴다. 이것이 요구 6 의 "사용자가 이름을 직접 주면" 이 들어오는 문이다.

### 복사 대상

| 후보 경로 | 판정 | 처리 |
|---|---|---|
| 에픽 폴더 전체 (`docs/epics/<에픽 폴더>/`) | `git ls-files -- <경로>` 가 비면 미추적 (무시 목록에 있든 없든) | 자식 워크트리의 같은 경로로 복사 |
| 방금 끝낸 파트의 피처 폴더 (`docs/features/<폴더>/`) | 같은 판정 | 같은 처리 |
| 위 경로가 추적 중일 때 | 자식이 커밋으로 물려받는다 | 복사하지 않는다 |
| 자식 쪽에 이미 있을 때 | 워크트리가 방금 생겨 없어야 정상 | 복사하지 않고 알린다 |

후보를 인수인계 목록이 아니라 폴더 단위로 잡는다. 예상도는 인수인계에서 읽으라고 지목하지 않지만 에픽 폴더에 있으므로 함께 복사되고, 그래야 성공 기준 4 (에픽 파일 셋) 가 성립한다. 인수인계가 지목하는 파일은 모두 이 두 폴더 안에 있으므로 요구 8 도 그대로 성립한다.

### 브랜치 이름

```
<에픽 워크트리 이름>__ep_part<번호>_<작업명>
```

| 조각 | 규칙 |
|---|---|
| 에픽 워크트리 이름 | 현재 브랜치가 규칙에 맞으면 그 앞부분. 맞지 않으면 현재 브랜치 전체 (에픽 워크트리 자신이 첫 파트) |
| 번호 | 현재 브랜치에서 읽은 번호에 1 을 더한다. 읽을 번호가 없으면 2 |
| 작업명 | 다음 파트 주제에서 짓는다. 공백은 하이픈으로. `__` 와 `/` 는 넣지 않는다 (앞은 구분자, 뒤는 폴더 중첩) |

### 부모 기록

워크트리 생성 스킬이 이미 남기는 git config 키를 그대로 읽는다. 새 키는 만들지 않는다.

| 키 | 값 |
|---|---|
| `branch.<자식>.js-super-parent` | 부모 브랜치 이름 |
| `branch.<자식>.js-super-parent-base` | 갈라진 커밋 |

### 인사 메시지 (자식 → 부모)

첫 줄이 미리보기로 보이므로 첫 줄에 무엇인지 적는다. 부모 세션의 대화가 압축됐어도 처리할 수 있도록 메시지 자체가 할 일을 담는다.

```
에픽 파트 인수인계 요청 — <자식 브랜치> 세션이 준비됐습니다
세션 이름: <자식 세션 이름>
워크트리: <자식 워크트리 경로>
브랜치: <자식 브랜치> (부모: <부모 브랜치>)
이 메시지를 받은 부모 세션은 SendMessage 로 위 세션 이름에 인수인계를 보내주세요.
내용은 다음 파트 주제와 이유 · 이번 파트의 결정과 버린 안과 함정 · 읽을 파일 경로 · 부모 브랜치 이름입니다.
```

### 인수인계 메시지 (부모 → 자식)

```
에픽 파트 인수인계 — 다음 파트: <주제>
## 다음 파트
<주제와 고른 이유>
## 이번 파트에서 정한 것
```

## 4. 외부 인터페이스

세션 사이의 계약과 스킬 사이의 호출 계약이다.

| 인터페이스 | 방향 | 계약 |
|---|---|---|
| 세션 찾기 | 자식 → 목록 | 같은 기기의 세션 목록에서 이름에 부모 브랜치 이름이 들어 있는 행을 고른다. 정확히 하나면 그 행. 여럿이면 이름 끝이 부모 브랜치와 일치하는 행으로 좁히고, 그래도 하나가 아니면 후보 목록을 보여주고 `AskUserQuestion` 으로 고르게 한다. 하나도 없으면 요구 13 의 안내 |
| 자기 세션 이름 | 세션 → 자신 | `ListAgents` 결과의 첫 줄 ("This session is <이름>") 에서 읽는다. 부모는 안내 단계에서, 자식은 인사를 쓸 때 쓴다 |
| 인사 | 자식 → 부모 | §3 의 인사 메시지. 한 번만 보낸다 |
| 인수인계 | 부모 → 자식 | §3 의 인수인계 메시지. 인사가 도착한 뒤에만 보낸다 |
| 마무리 호출 | 마무리 스킬 → epic-close | 이름으로 부른다. 인자 없음. epic-close 가 스스로 발동 조건을 검사한다 |
| 수동 호출 | /epic-next → epic-close | 이름으로 부른다. 인자 없음 |
| 다음 파트 시작 | /epic-handoff → brainstorming | 이름으로 부르며 인자로 다음 파트 주제만 넘긴다. 결정과 함정은 대화에 도착한 인수인계 메시지에 있으므로 브레인스토밍이 그 메시지를 읽는다 (§2 브레인스토밍 행의 한 줄) |
| 부모 무응답 | 사용자 → 자식 | 자식은 인사를 보낸 뒤 "인수인계를 기다립니다. 오지 않으면 '그냥 시작' 이라고 입력하세요" 를 내고 턴을 마친다. 시간 제한은 두지 않는다. 사용자가 그렇게 입력하면 인수인계 없이 브레인스토밍을 시작한다 |
| 세션 이름 관례 | 사용자 → 세션 | 세션 이름에 그 워크트리의 브랜치 이름이 들어 있어야 한다. 부모는 안내 단계에서 자기 이름을 확인하고, 자식은 이 관례로 부모를 찾는다 |

세션 목록과 메시지 전송은 Claude Code 가 제공하는 `ListAgents` 와 `SendMessage` 도구다. 다른 하네스에서는 메시지가 오가는 단계만 빠진다. epic-close 는 인사 대기 단계 대신 "이 환경은 세션 간 인수인계를 지원하지 않습니다. 새 세션에서 `/brainstorm <주제>` 로 시작하세요" 한 줄을 내고 끝나며, 그 앞의 갱신·커밋·선택·생성·안내는 그대로 돈다. `/epic-handoff` 는 같은 한 줄을 내고 `AskUserQuestion` 으로 곧바로 브레인스토밍을 시작할지 묻는다.

## 5. 핵심 결정 + 대안 비교

### 결정 1 — 마무리 절차는 새 스킬 하나에 두고 마무리 스킬이 부른다

| 안 | 무엇이 달라지는가 | 무엇을 포기하는가 | 되돌리는 비용 |
|---|---|---|---|
| 새 스킬 epic-close, 마무리 스킬 끝에서 한 줄 호출 (채택) | 절차가 한 곳. 실행 경로 둘과 수동 커맨드가 같은 것을 부른다 | 스킬 설명 한 줄이 매 세션 상주한다 | 스킬 삭제와 호출 한 줄 제거 |
| 인라인 실행 스킬과 보조 에이전트 실행 스킬에 각각 인라인 | 새 스킬 없음 | 같은 절차의 사본 둘. 한쪽만 고치면 실행 방식에 따라 동작이 갈린다 | 두 곳 제거 |
| 마무리 스킬 본문에 직접 | 새 스킬 없음, 사본도 없음 | 마무리 스킬이 테스트·종료 메시지·에픽 세 가지 일을 갖는다. 2개 문서 트랙의 수동 진입이 테스트 실행까지 끌고 온다 | 본문에서 잘라내기 |

마무리 스킬은 인라인과 보조 에이전트 두 경로가 이미 마지막에 부르는 유일한 공통 지점이다. 거기서 한 줄로 부르면 두 경로를 고치지 않아도 된다. 이 권장이 깨지는 조건은 마무리 스킬이 어느 실행 경로에서 빠지는 경우다. 그때는 그 경로가 epic-close 를 직접 불러야 한다.

### 결정 2 — 2개 문서 트랙은 수동 커맨드로 들어온다

| 안 | 무엇이 달라지는가 | 무엇을 포기하는가 | 되돌리는 비용 |
|---|---|---|---|
| `/epic-next` 커맨드 + 2개 확정 종료 안내에 한 줄 (채택) | 실행이 스킬 밖에서 끝나도 들어올 문이 있다. 사용자가 잊지 않도록 종료 시점에 알려준다 | 자동은 아니다. 사용자가 한 번 쳐야 한다 | 커맨드 삭제 |
| 변경이력에 코드 수정 항목이 붙을 때 발동 | 자동 | 코드 수정 항목은 실행 중에도 여러 번 붙는다. "끝났다" 는 신호가 아니다 | — |
| 세션 시작 훅에서 감지 | 자동 | 무엇이 끝났는지 훅은 모른다. 매 세션 오탐 | — |

2개 문서 트랙은 구현계획서 없이 사용자가 직접 구현한다. 스킬이 실행을 감싸지 않으므로 끝났다는 신호를 만들 곳이 없다. 자동화할 수 없는 자리는 자동화하지 않고, 잊지 않게 하는 데 집중한다.

### 결정 3 — 이름은 평탄형이다

| 안 | 무엇이 달라지는가 | 무엇을 포기하는가 | 되돌리는 비용 |
|---|---|---|---|
| `결제__ep_part3_정산` (채택) | 짧다. 번호로 순서가 보인다 | 이름만으로는 어느 파트에서 갈라졌는지 모른다. 부모 기록이 갖고 있다 | 이름 규칙 한 줄 |
| `결제__ep_part2_환불__ep_part3_정산` (누적) | 기존 워크트리 규칙과 같다. 이름만으로 계보가 보인다 | 파트가 늘수록 이름이 길어진다 | 이름 규칙 한 줄 |

사슬이 앞으로만 가고 형제가 없으므로 계보는 번호와 부모 기록으로 충분하다. 사용자가 이름을 직접 주면 어느 규칙도 적용하지 않는다.

### 결정 4 — 자식이 먼저 인사한다

요구사항서 §세션 인수인계의 표를 그대로 따른다. 부모는 자식이 언제 뜨는지 알 수 없고, 세션 목록을 반복해서 확인하는 것은 도구 계약이 금지한다. 인사 메시지는 스스로 할 일을 설명한다. 부모 세션의 대화가 그 사이에 압축돼도 메시지만 보고 처리할 수 있게 하기 위해서다.

### 결정 5 — 인수인계 초안을 파일로 남기지 않는다

| 안 | 무엇이 달라지는가 | 무엇을 포기하는가 | 되돌리는 비용 |
|---|---|---|---|
| 인사가 오면 그때 작성해 보낸다 (채택) | 산출물 없음. 흐름이 요구사항서 그대로다 | 인사가 늦으면 부모의 대화가 압축돼 있을 수 있다. 그때는 피처 문서의 변경이력과 기술설계의 결정·위험 섹션에서 다시 모은다 | — |
| 안내 시점에 초안을 자식 워크트리의 무시 폴더에 써 두고, 인사가 오면 그 파일을 보낸다 | 압축에 강하다. 부모가 답하지 않을 때 자식이 파일을 읽는 대체 경로가 생긴다 | 산출물 하나 추가. 메시지 흐름이 사실상 파일 전달이 된다 | 파일 쓰기 삭제 |

인수인계에 들어가는 네 가지는 모두 피처 문서에 근거가 남아 있는 것들이다. 압축돼도 다시 모을 수 있으므로 파일을 하나 더 만들지 않는다. 부모가 답하지 않는 경우의 판정 장치는 §4 의 "부모 무응답" 행이다. 자식은 시간을 재지 않고 사용자 입력으로 대체 경로에 들어간다.

### 결정 6 — 이름·경로 계산은 스크립트가 한다

| 안 | 무엇이 달라지는가 | 무엇을 포기하는가 | 되돌리는 비용 |
|---|---|---|---|
| 새 스크립트 하나 (채택) | 브랜치 파싱과 다음 이름과 미추적 판정이 결정적이다. 단위 테스트로 잡는다 | 파일 하나 추가 | 삭제 |
| 기존 에픽 스캔 스크립트에 함수 추가 | 파일 추가 없음 | 스캔 스크립트는 문서 폴더만 읽는다. git 을 읽는 함수가 섞이면 역할이 둘이 된다 | 함수 이동 |
| 스킬 본문에서 모델이 계산 | 스크립트 없음 | 번호 계산과 이름 조립을 매번 다르게 할 수 있다. 미추적 판정은 git 명령이 필요해 어차피 도구 호출이다 | — |

### 결정 7 — 갱신 커밋은 에픽 폴더만 담는다

갱신 커밋은 에픽 폴더의 파일만 명시해서 담는다. 작업 트리에 남은 다른 변경은 담지 않는다. 에픽 폴더가 git 에 무시돼 있으면 커밋할 것이 없으므로 이 단계는 건너뛰고 한 줄 알린다. 워크트리 생성 스킬의 dirty 게이트가 그 뒤에 남은 변경을 다룬다.

## 6. 위험/사이드이펙트

| 위험 | 분류 | 내용 | 완화 |
|---|---|---|---|
| 쉬고 있는 부모 세션이 인사에 깨어나지 않음 | race | 세션 간 메시지가 "다음 도구 호출 시점" 에 전달된다는 계약이라, 턴을 마친 세션이 바로 깨어난다는 보장을 문서에서 확인하지 못했다 | 사람이 돌리는 시나리오에서 첫 번째로 확인한다. 안 깨어나면 이 설계의 전제가 깨진 것이므로 요구사항으로 돌아가 인사 방식을 다시 정한다. 사용자가 부모 세션에 입력하는 경로는 요구사항이 버린 안이라 완화책으로 쓰지 않는다 |
| 인사 시점에 부모 대화가 압축됨 | side-effect | 인수인계 내용을 대화에서 못 꺼낸다 | 인사 메시지가 할 일을 담는다. 내용은 피처 문서에서 다시 모은다 (결정 5) |
| 세션 이름이 관례를 안 따름 | side-effect | 자식이 부모를 못 찾는다 | 부모가 안내 단계에서 자기 이름을 확인하고 바꾸도록 안내한다. 자식은 요구 13 의 안내를 낸다 |
| 마무리 스킬을 부르는 다른 흐름 (og, 자동) 에서 epic-close 가 돎 | side-effect | 원치 않는 발동 | 발동 조건 (진행 중 에픽 + 소속 표식) 을 epic-close 안에서 검사한다. og 와 자동 브레인스토밍은 소속 표식을 남기지 않는다. 표식이 붙은 피처를 자동 실행 커맨드로 실행한 경우는 원하는 발동이다 |
| 이번 파트 판별이 다른 소속 피처를 고름 | side-effect | 최근 수정 기준이라 옆 피처의 문서를 막 고친 뒤면 그쪽이 잡힌다 | 어느 폴더를 골랐는지 한 줄 알리고, `/epic-next <피처 폴더>` 로 지정할 수 있게 한다 |
| 브레인스토밍의 마무리 단계 제거 | breaking | 기존 시나리오 (H25 시나리오 2 의 4번) 가 옛 동작을 기대한다 | H25 를 함께 고친다 |
| 갱신 커밋이 무관한 변경을 담음 | side-effect | 실행이 남긴 다른 파일이 에픽 커밋에 섞인다 | 에픽 폴더 경로만 명시해 담는다 (결정 7) |
| 미추적 문서 복사가 자식의 파일을 덮음 | side-effect | 자식 워크트리는 방금 만들어져 그 경로가 비어 있다 | 대상 경로가 이미 있으면 복사하지 않고 알린다 |
| 계획서의 코드 블록 안에 코드 블록이 겹침 | side-effect | 이 기능의 원인이었던 잘림이 이번 계획서에서 되풀이될 수 있다. 스킬 본문에는 마크다운 예시가 들어간다 | 계획서의 바깥 블록은 백틱 네 개로 연다. 실행 뒤 스킬 파일 끝부분이 계획서와 같은지 확인한다 |
| 워크트리 생성 스킬의 이름 제안이 개입 | side-effect | 이름을 제안하려 들어 규칙을 덮어쓴다 | 이름을 명시해서 부른다. 명시 이름은 그대로 쓴다는 규칙이 있다 |

## 7. 테스트 전략

| 층 | 대상 | 방법 |
|---|---|---|
| 단위 | 새 스크립트의 네 함수 | pytest. 규칙에 맞는 브랜치 / 맞지 않는 브랜치 / 번호 없는 브랜치 / 작업명의 공백·구분자 처리 / 추적·무시·미추적 경로 판정 / 소속 피처 중 최근 수정 폴더 판별 |
| 결합 | 스킬과 커맨드 본문 | CLAUDE.md 결합 메모의 읽기 전용 검사. 마무리 스킬이 epic-close 를 부르는가, 브레인스토밍에 마무리 단계가 남아 있지 않은가, 관련 스킬 헤더가 있는가, 두 커맨드가 명시 호출 전용인가, 커맨드와 스킬 이름이 겹치지 않는가 |
| 사람이 돌리는 e2e | 전체 흐름 | H27 시나리오. 임시 저장소에 에픽과 파트를 만들고 실행 끝을 흉내 내 마무리를 돌린다. 워크트리와 부모 기록과 안내를 확인한다. 두 번째 터미널에서 자식 커맨드를 쳐서 인사와 인수인계와 브레인스토밍 시작을 확인한다. 에픽 폴더를 무시 목록에 넣고 복사를 확인한다. 에픽이 없는 저장소에서 실행 끝에 출력이 없는지 확인한다 |
