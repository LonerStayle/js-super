# 개발방향: 미라클모닝

> **다음 단계 안내**: 이 문서는 기술 설계서입니다 (아키텍처 / 컴포넌트 / 데이터 / 인터페이스 / 결정 / 위험 / 테스트 전략). `미라클모닝-requirements.md` (PRD) 를 기반으로 작성되고, 다음 단계 `미라클모닝-implementation-plan.md` (단계별 계획) 의 입력이 됩니다. 다음 단계로 `writing-plans` skill (또는 `/write-plan` 슬래시) 을 호출해서 구현 계획을 만드세요. 단계별 구현 task 는 여기 박지 마세요 — 그건 다음 산출물 (plan) 에 들어갑니다.

## 1. 아키텍처 개요

두 개의 instruction-only 슬래시 커맨드로 구성한다. 코드 실행 스크립트를 새로 만들지 않고, 커맨드 본문의 지시를 메인 에이전트가 읽고 git 명령과 파일 읽기/쓰기로 수행한다. (이 저장소의 `/new-skill`, `/list-skills` 와 같은 방식)

### 저장 커맨드 (`/goodnight`) 흐름

1. **최상위 워크트리 판별**: `git worktree list` 의 첫 줄이 최상위 워크트리(main working tree)다. 현재 커맨드를 실행한 워크트리 경로가 그 첫 줄과 같은지 확인한다. 다르면 저장하지 않고 "이 커맨드는 최상위 워크트리(`<경로>`)에서 실행하세요"라고 안내하고 종료한다. (FR-5)
2. **워크트리 열거**: `git worktree list` 로 최상위 + 하위 워크트리 전체의 경로·브랜치·HEAD 를 얻는다. (FR-2)
3. **워크트리별 활동 수집 (병렬 보조 에이전트)**: 워크트리 하나당 보조 에이전트 하나를 병렬로 호출한다. 각 보조 에이전트는 담당 워크트리에 대해 다음을 조사하고, "진행상황 / 다음 할 일 / 주의점 / 위험신호" 네 항목의 구조화 요약만 돌려준다. (FR-3, FR-4)
   - git 상태: 브랜치, 최근 커밋 몇 개, `git status` 로 본 미커밋 변경, 최상위 브랜치 대비 ahead/behind
   - 진행 문서: 해당 워크트리의 `docs/features/` 아래 최신 requirements/tech-design/implementation-plan 과 각 문서의 최신 변경이력 항목
   - 세션 기록: `~/.claude/projects/<경로-슬러그>/` 의 세션 기록(`.jsonl`)을 깊게 분석해 최근 작업 내용·결정·미완료 사항 파악 (사용자 선택: 깊은 분석)
4. **취합 + 위험 자동 판정**: 메인 에이전트가 각 보조 에이전트의 요약을 모은다. 위험신호(예: 미커밋 대량 변경, 실패한 테스트 흔적, 미완료 배포, 해결 안 된 충돌, 사용자가 남긴 명시적 경고 요청)를 종합해 프로젝트 전체 위험도를 판정한다. 위험이 있으면 경고 배너를 만들고, 없으면 배너를 만들지 않는다. (FR-7, FR-8)
5. **노트 작성 + 저장**: 취합 결과를 `.js-super/session-handoff/YYYY-MM-DD.md` 에 저장한다. 같은 날짜 파일이 이미 있으면 덮어써 최신 상태로 갱신한다. (FR-6)

### 읽기 커맨드 (`/goodmorning`) 흐름

1. 최상위 워크트리의 `.js-super/session-handoff/` 에서 가장 최근 날짜의 노트 파일을 찾는다. (FR-9)
2. 노트가 없으면 "저장된 핸드오프 노트가 없습니다. 최상위 워크트리에서 `/goodnight` 먼저 실행하세요"라고 안내한다.
3. 경고 배너가 있으면 브리핑 맨 앞에 크게 먼저 출력하고, 이어서 워크트리별 진행상황 요약을 출력한다. 배너가 없으면 워크트리별 요약만 담백하게 출력한다. (FR-10)
4. 읽기는 어느 워크트리에서 실행해도 최상위 노트를 찾아 읽는다(읽기는 파괴적 동작이 아니므로 실행 위치를 막지 않는다). 저장만 최상위 전용이다.

### 세션 기록 깊은 분석과 메인 컨텍스트 보호

세션 기록을 깊게 파면 워크트리·세션이 많을 때 실행이 무거워진다. 이를 워크트리별 병렬 보조 에이전트로 분산해, 각 에이전트가 담당 워크트리의 세션 기록만 읽고 요약만 반환하게 한다. 메인 에이전트는 원본 세션 기록 전체를 직접 읽지 않고 요약만 취합한다.

## 3. 데이터 모델/스키마 변경 (핸드오프 노트 파일 구조)

DB/스키마 변경은 없다. 대신 핸드오프 노트 파일의 구조를 정의한다.

- **경로**: 최상위 워크트리 기준 `.js-super/session-handoff/YYYY-MM-DD.md`. 날짜별 누적, 같은 날 재실행 시 덮어쓰기.
- **파일 구조**:

```markdown
# 미라클모닝 핸드오프 — YYYY-MM-DD HH:MM

<!-- 경고 배너 영역: 위험 판정 시에만 존재. 없으면 이 영역 자체를 생략 -->
🚨 (위험 있을 때만) 경고 배너 본문

## 개요
- 최상위 워크트리: <경로>
- 워크트리 수: N

## 워크트리: <이름> [<브랜치>]
### 진행상황
### 다음 할 일
### 주의점

<!-- 워크트리마다 위 섹션 반복 -->
```

- 경고 배너 영역은 위험 판정 시에만 채운다(FR-8). 판정 결과 위험이 없으면 배너 영역 자체가 파일에 없다.
- 워크트리마다 독립 섹션으로 나눠 서로 섞이지 않게 한다(FR-3).

## 5. 핵심 결정 + 대안 비교

- **결정 1 — instruction-only 커맨드**: 코드 실행 스크립트 없이 커맨드 본문 지시로 동작.
  - 대안: 워크트리 열거·세션 파싱용 Python helper 스크립트 신설.
  - 선택 이유: NFR-1(무의존성) + 저장소 관례(`/new-skill` 등). 세션 기록 요약·위험 판정은 LLM 강점 영역이라 스크립트가 대체하기 어렵다.
- **결정 2 — 워크트리별 병렬 보조 에이전트**: 수집을 워크트리 단위로 분산.
  - 대안: 메인이 모든 워크트리의 세션 기록을 순차로 직접 읽기.
  - 선택 이유: 세션 기록 깊은 분석(사용자 선택)을 하면서도 메인 컨텍스트 폭발을 막는다. 각 에이전트가 담당 워크트리만 깊게 읽고 요약만 반환한다.
- **결정 3 — 데이터 소스 = git + 진행 문서 + 세션 기록 종합**: 세 소스를 함께 본다.
  - 대안: git + 진행 문서만.
  - 선택 이유: 대표님이 세션 대화 내용까지 반영하기를 원함. 속도·무게 트레이드오프는 §6에서 완화한다.
- **결정 4 — 날짜별 파일 누적**: `.js-super/session-handoff/YYYY-MM-DD.md`.
  - 대안: `latest.md` 하나만 덮어쓰기.
  - 선택 이유: 지난 기록 보존 + 아침엔 최신 우선. (사용자 선택)
- **결정 5 — 최상위 워크트리 판별 = `git worktree list` 첫 항목**: 첫 줄이 main working tree.
  - 대안: `.git` 파일/디렉토리 검사, 환경변수.
  - 선택 이유: git 표준이라 안정적. 저장 커맨드는 이 위치에서만 허용(FR-5).

## 6. 위험/사이드이펙트 (preliminary)

- **side-effect**: 세션 기록 깊은 분석 → 워크트리·세션이 많으면 실행 시간과 토큰이 급증한다. 완화: 워크트리별 병렬 보조 에이전트 분산 + 각 에이전트에 "최신 세션 우선, 오래된 세션은 요약 위주" 지시.
- **side-effect**: `.js-super/session-handoff/YYYY-MM-DD.md` 같은 날 덮어쓰기 → 같은 날 이전 저장 내용이 사라진다. 완화: 하루 마무리 1회 실행 전제 + 재실행은 의도적 최신 갱신. 필요 시 향후 타임스탬프 suffix 확장 여지.
- **side-effect**: 경고 자동 판정이 LLM 판단이라 위험을 놓치거나 과하게 경고할 수 있다. 완화: 커맨드 본문에 위험 신호 체크리스트를 명시(미커밋 대량 변경 / 실패한 테스트 흔적 / 미완료 배포 / 해결 안 된 충돌 / 사용자 명시 경고 요청).
- **breaking**: 없음 — 신규 커맨드라 기존 skill/command 동작을 바꾸지 않는다.
- **race**: 여러 워크트리에서 커맨드를 동시에 실행하면 같은 노트 파일에 경합이 날 수 있다. 1인 순차 실행 전제라 가능성은 낮다. 인지만 하고 별도 잠금은 두지 않는다.

## 7. 테스트 전략

instruction-only 커맨드라 자동화 유닛 테스트는 없다. 저장소 관례대로 dogfood 수동 시나리오로 검증한다.

- **S1**: 최상위 워크트리에서 `/goodnight` 실행 → 현재 프로젝트의 모든 워크트리(현재 5개)가 각각 "진행상황 / 다음 할 일 / 주의점" 섹션으로 노트에 생성되는지. (FR-2, FR-3)
- **S2**: 하위 워크트리에서 `/goodnight` 실행 → 저장하지 않고 최상위 경로를 안내하는지. (FR-5)
- **S3**: 미커밋 대량 변경 같은 위험 상태 → 경고 배너 생성 / 깨끗한 상태 → 배너 없음. (FR-7, FR-8)
- **S4**: `/goodmorning` 실행 → 가장 최근 날짜 노트가 브리핑으로 출력되고, 배너가 있으면 맨 앞에 먼저 나오는지. (FR-9, FR-10)
- **S5**: 노트와 브리핑에 비유법 표현·불필요한 용어 병기가 없는지 육안 확인. (FR-11)
