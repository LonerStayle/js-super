# 요구사항: 미라클모닝

> **다음 단계 안내**: 이 문서는 PRD (기획 단계 요구사항만) 입니다. 다음 단계로 `tech-design` skill (또는 `/tech-design` 슬래시) 을 호출해서 `미라클모닝-tech-design.md` (기술 설계서) 를 만드세요. 기술 결정이나 구현 세부사항은 여기 박지 마세요 — 그건 다음 두 산출물에 들어갑니다.

## 1. 배경/목적

한 프로젝트를 여러 워크트리로 나눠 병렬 작업하는 상황에서, 다음 날 아침 출근했을 때 "각 워크트리에서 어디까지 했고, 다음에 무엇을 해야 하고, 무엇을 주의해야 하는지"를 한눈에 파악하기 어렵다. 워크트리가 여러 개면 머릿속으로 상태를 복원하는 데 시간이 든다.

목적은 두 개의 슬래시 커맨드로 이 문제를 없애는 것이다. 밤에 작업을 마칠 때 커맨드 하나로 모든 워크트리의 진행상황과 주의사항을 하나의 핸드오프 노트에 저장하고, 아침에 다른 커맨드 하나로 그 노트를 브리핑 형태로 다시 읽는다. 위험하거나 꼭 기억해야 할 일이 있으면 노트 맨 위에 눈에 확 띄는 경고 배너가 붙어 아침에 놓치지 않게 한다.

## 2. 사용자 스토리 / 시나리오

- 저녁 시나리오: 대표님이 여러 워크트리에서 하루치 작업을 마친다. 최상위 워크트리에서 저장 커맨드를 실행하면, 각 워크트리의 상태가 워크트리별로 정리된 핸드오프 노트가 만들어진다. 위험한 일이 있으면 경고 배너까지 함께 박힌다.
- 아침 시나리오: 다음 날 출근해서 읽기 커맨드를 실행하면, 저장해둔 노트가 브리핑으로 출력된다. 경고가 있으면 맨 먼저 크게 보이고, 없으면 담백한 진행상황 요약만 보인다.

## 3. 기능 요구사항 (FR)

### 커맨드 구조

- **FR-1**: 기능은 두 개의 슬래시 커맨드로 나눈다. 하나는 저녁에 상태를 저장하는 커맨드, 다른 하나는 아침에 그 상태를 읽는 커맨드다. (커맨드 이름 제안: 저장 = `/goodnight`, 읽기 = `/goodmorning`. 최종 이름은 리뷰에서 확정한다.)

### 저장 커맨드 (저녁)

- **FR-2**: 저장 커맨드는 현재 프로젝트에 연결된 모든 워크트리(최상위 워크트리 + 하위 워크트리 전체)를 자동으로 찾아 각각의 활동을 파악한다.
- **FR-3**: 워크트리별로 파악하는 내용은 최소한 다음을 포함한다 — (a) 어디까지 진행했는지, (b) 다음에 무엇을 해야 하는지, (c) 주의하거나 염두해야 할 점. 각 워크트리 섹션은 서로 명확히 구분되어, "A 워크트리는 이것, B 워크트리는 저것"이 뒤섞이지 않는다.
- **FR-4**: 활동 파악은 Claude가 자동으로 초안을 만든다. 그 위에 대표님이 "이건 꼭 강조" 같은 내용을 덧붙이면 노트에 반영한다. (자동 초안 + 사용자 보강)
- **FR-5**: 저장 커맨드는 **최상위 워크트리에서 실행하는 것을 전제**로 한다. 하위 워크트리에서 실행하면 저장하지 않고, "이 커맨드는 최상위 워크트리(`<최상위 경로>`)에서 실행하세요"라고 안내한다.
- **FR-6**: 완성된 핸드오프 노트는 최상위 워크트리 아래 저장소 관례 위치(`.js-super/` 계열, gitignored)에 저장한다.

### 경고 배너 (자동 판정)

- **FR-7**: 저장 시 Claude가 각 워크트리 상태를 보고 위험도를 **자동으로 판정**한다. 대표님이 경고 강도를 직접 지정하지 않는다.
- **FR-8**: 위험하거나 꼭 기억해야 할 일이 있다고 판정되면, 노트 맨 위에 눈에 확 띄는 경고 배너를 박는다. 판정 결과 그런 일이 없으면 배너 없이 담백하게 둔다. (경고가 없는데 억지로 배너를 만들지 않는다.)

### 읽기 커맨드 (아침)

- **FR-9**: 읽기 커맨드는 저장해둔 최신 핸드오프 노트를 브리핑 형태로 출력한다.
- **FR-10**: 경고 배너가 있으면 브리핑 맨 앞에 크게 먼저 보여준다. 없으면 워크트리별 진행상황 요약만 담백하게 보여준다.

### 출력 스타일 (사람이 읽기 위한 글)

- **FR-11**: 노트와 브리핑은 사람이 읽기 위한 명확한 한국어로 쓴다. 다음을 지킨다 —
  - 불필요한 용어 병기를 하지 않는다 (예: "안녕(hi)"처럼 기술 문서 설명하듯 원어를 괄호로 덧붙이지 않는다).
  - **비유법으로 설명하지 않는다.** 원래 의미가 희석되거나 오해를 부를 수 있는 비유·은유 표현을 절대 쓰지 않고, 사실을 그대로 적는다.

## 4. 비기능 요구사항 (NFR)

- **NFR-1**: 저장 커맨드는 지시문만 담긴 instruction-only 슬래시 커맨드로 만든다. 별도 실행 스크립트/외부 의존성을 새로 추가하지 않는다. (이 저장소의 `/new-skill`, `/list-skills` 커맨드와 같은 방식)
- **NFR-2**: 워크트리 수가 많아지면 핸드오프 노트 분량이 커질 수 있다. 이는 정상이며, 워크트리마다 독립 섹션으로 나눠 가독성을 유지한다.

## 5. 범위 밖 (Out of Scope)

- 정해진 시각에 자동 실행(cron/스케줄)하는 기능 — 대표님이 커맨드를 직접 실행한다. (대화 중 명시)
- 현재 프로젝트가 아닌 다른 저장소의 워크트리 파악 — 현재 프로젝트에 연결된 워크트리만 대상. (대화 중 명시)
- 경고 강도의 사용자 수동 지정 — 자동 판정만. (경고 판정 질문에서 "자동 판정만" 선택)
- 세션 대화 전체를 그대로 옮겨 적는 것 — 파악한 내용을 요약해 정리한다. (대화 중 명시)

## 6. 수용 기준 (Acceptance Criteria)

- 최상위 워크트리에서 저장 커맨드를 실행하면, 프로젝트의 모든 워크트리가 각각 독립 섹션으로 정리된 핸드오프 노트가 `.js-super/` 계열 위치에 생성된다.
- 하위 워크트리에서 저장 커맨드를 실행하면, 저장하지 않고 최상위 워크트리 경로를 안내한다.
- 위험 사항이 있으면 노트 맨 위에 경고 배너가 있고, 없으면 배너가 없다.
- 아침에 읽기 커맨드를 실행하면 최신 노트가 브리핑으로 출력되고, 경고 배너가 있으면 맨 앞에 먼저 크게 보인다.
- 노트와 브리핑 어디에도 비유법 표현과 불필요한 용어 병기가 없다.
