# 요구사항: 워크트리 재분기 네이밍

## 배경

`/js-super:worktree` (setting-up-worktrees skill) 는 v2.9.0 부터 워크트리 안에서 호출하면 호출 위치 HEAD 기준으로 재분기한다. 그런데 지금은 새 브랜치 이름을 사용자가 준 그대로 쓸 뿐, 부모 브랜치와의 관계가 이름에 남지 않는다. 워크트리가 여러 개 쌓이면 어느 브랜치가 어느 브랜치에서 갈라져 나왔는지 이름만 보고는 알 수 없다.

사용자는 네이밍 자체를 어려워해서, 이름을 직접 짓기보다 AI 가 지어서 제안해 주길 원한다. 재분기일 때는 `부모브랜치__자식이름` 처럼 `__` 구분자로 부모 관계가 드러나는 이름이면 좋겠다는 것이 출발점이다 (예: `feat/scheduled-tasks` 에서 재분기 → `feat/scheduled-tasks__hihi`).

## 핵심 결정

대화에서 좁혀진 방향과, 검토 후 버린 대안은 다음과 같다.

**채택 — AI 네이밍 제안 방식.** 워크트리 생성 시점마다 (메인에서 처음 만들 때든, 워크트리 안에서 재분기할 때든) 메인 에이전트가 브랜치 이름을 생성해 제안한다. 재분기일 때는 `부모__자식` 규칙을 제안 이름에 적용한다. 사용자가 이름을 명확히 준 경우에는 그 이름을 그대로 존중한다.

**버림 — 강제 자동 프리픽스.** 재분기 시 사용자가 준 이름 앞에 무조건 `부모__` 를 붙이는 방식. 사용자가 명시적으로 원하지 않았다 (질문 1 답변 "후자야"). 규칙이 강제되면 사용자가 의도한 이름을 덮어쓰는 부작용도 있다.

**버림 — 안내만 하는 방식.** "이런 이름을 권장합니다" 문구만 출력하고 이름은 사용자가 짓는 방식. 사용자가 네이밍에 AI 도움을 받고 싶다고 했으므로, 안내만으로는 목적을 채우지 못한다.

## 인터랙션 흐름

- 사용자가 작업 설명만 주고 이름을 안 준 경우 (예: "스케줄 알림 기능 워크트리 만들어줘") → AI 가 이름을 생성해 제안한다.
- 워크트리 안에서 재분기하는 경우 → 제안 이름은 `부모브랜치명__자식이름` 형식을 따른다.
- 메인 (재분기 아님) 에서 만드는 경우 → 접두어 없이, 저장소의 기존 브랜치 관례를 참고해 짓는다.
- 제안 이름을 확인받고 만들지, 바로 만들고 알림만 줄지는 상황에 따라 메인 에이전트 재량이다 (질문 3 답변). 단, 바로 만든 경우에도 어떤 이름으로 만들었는지 반드시 알린다.

## 요구 항목

**FR-1**: 워크트리 생성 시 사용자가 브랜치 이름을 명확히 주지 않으면 (작업 설명만 주면), 메인 에이전트가 브랜치 이름을 생성해 제안한다. 적용 시점은 메인에서의 최초 생성과 워크트리 안 재분기 모두다.

**FR-2**: 워크트리 안에서 재분기할 때 AI 제안 이름은 `<부모브랜치명>__<자식이름>` 형식을 따른다. 구분자는 밑줄 두 개 (`__`) 다.

**FR-3**: 다단계 재분기 시 이름은 누적된다. `feat/scheduled-tasks__hihi` 에서 다시 재분기하면 `feat/scheduled-tasks__hihi__<자식이름>` 이 된다.

**FR-4**: 사용자가 브랜치 이름을 명시적으로 준 경우 그 이름을 그대로 쓴다. 네이밍 규칙을 강제로 덮어씌우지 않는다.

**FR-5**: 제안 이름의 확정 방식 (사용자 확인 후 생성 / 즉시 생성 후 알림) 은 상황에 따라 메인 에이전트가 판단한다. 즉시 생성한 경우에도 생성된 이름을 사용자에게 알린다.

**FR-6**: 메인에서의 최초 생성 시 AI 제안 이름은 부모 접두어 없이 짓되, 저장소의 기존 브랜치 이름 관례 (언어, 스타일, `feat/` 류 접두어 사용 여부) 를 참고한다.

## 우려와 해결

- **브랜치명 속 `/` 와 워크트리 폴더 경로**: `feat/scheduled-tasks__hihi` 같은 이름은 `.worktrees/` 아래에서 폴더가 중첩될 수 있다. 폴더 이름을 브랜치명과 어떻게 대응시킬지는 기술설계에서 정한다.
- **`__` 가 이미 든 이름과의 모호성**: 사용자가 원래 `__` 를 쓰는 이름을 명시하면 그대로 존중하므로 (FR-4) 충돌하지 않는다. AI 제안 이름에서만 `__` 가 부모-자식 구분 의미를 가진다.
- **이름 길이 누적**: 다단계 재분기 시 이름이 길어지지만, 부모 관계가 이름에 그대로 남는 쪽을 사용자가 택했다 (질문 4 답변). 길이 제한이나 축약은 도입하지 않는다.

## 범위 밖

- `worktree-merge-back` / `worktree-remove` 가 `__` 를 파싱해 부모 브랜치를 자동 판별하는 기능 — 이번 범위 밖. 이름 규칙이 정착된 뒤 별도 피처로 검토할 수 있다.
- 기존에 만들어진 워크트리 / 브랜치 이름의 소급 변경 — 하지 않는다.
- 강제 네이밍 규칙 (사용자 명시 이름 덮어쓰기) — 도입하지 않는다 (FR-4 와 동일 취지).
