# 사전 실측 노트 (Task 1)

측정 일시: 2026-08-15
측정 방법: 워크트리를 임시 디렉토리에 `rsync` 로 복사하고, 그 사본을 `--plugin-dir` 로 로드해 헤드리스로 두 번 실행.
원본 저장소는 읽기만 했고 임시 디렉토리는 종료 시 삭제했다.

이 노트는 스펙 산출물이 아니라 측정 기록이라 변경이력 footer 를 두지 않는다.

---

## 1. 실측값

| 항목 | 값 | 설계서의 값 | 차이 |
|---|---|---|---|
| 사본 생성 (`rsync -a --exclude .git`) | 1초 미만, 4.0MB | [실측] 0.13초 / 3.9MB | 일치 |
| 절차 세그먼트 1건 | **35.3초 / $0.477 / 7턴** | [추론] 120초 | **3.4배 빠름** |
| 보조 에이전트 케이스 1건 | **14.3초 / $0.233 / 2턴** | 없음 | 신규 |
| 턴 단가 | 5.0초/턴 | [실측 유도] 4.06초/턴 | 근사 일치 |
| Claude Code 버전 | 2.1.223 | 2.1.223 | 일치 |

세그먼트 소요가 설계서 추정의 3분의 1 이하다. 30분 제약 검산이 크게 여유로워진다.

## 2. 30분 검산 갱신

설계서 §7-2 의 공식 `T = 고정비 + max(예상시간 합 / 병렬수, 최장 케이스)` 에 실측값을 넣는다.

| 시나리오 | 설계서 예측 | 실측 반영 |
|---|---|---|
| 전형 (발동 8 + 세그먼트 4) | 4.8분 | **2.4분** |
| 영향 범위 최대 (발동 16 + 세그먼트 6) | 7.2분 | **3.6분** |

세그먼트가 35초라 최장 케이스 항이 지배하지 않는다. 설계서가 지목한 "기본 실행에 전체 흐름 케이스가 들어가면 깨진다" 는 전제는 그대로 유효하다.

## 3. 보조 에이전트 관측 신호 — 확정

실행 기록에서 다음 필드가 실제로 채워지는 것을 확인했다.

`parent_tool_use_id` / `task_id` / `tool_use_id` / `subagent_type` / `task_type` / `task_description` / `summary` / `status` / `output_file`

즉 보조 에이전트를 쓰는 케이스도 관측 가능하다. 설계서 §4-2 의 "미검증" 항목이 해소됐다.

**주의 하나**: 도구 이름이 `Task` 가 아니라 **`Agent`** 였다. 판정 로직에서 도구 이름을 하드코딩할 때 이 이름을 써야 한다.

비용은 `result.total_cost_usd` 한 값에 합산되어 나온다. 보조 에이전트 비용이 따로 분리되지는 않는다.

## 4. 예상 못 한 발견 — `--plugin-dir` 은 설치된 플러그인을 대체하지 않는다

이게 이번 측정에서 가장 중요한 결과다.

사본을 `--plugin-dir` 로 로드하고 `--setting-sources ""` 까지 줬는데도, 로드된 슬래시 목록에 **바뀐 이름과 옛 이름이 함께** 나왔다.

```
js-super:design-tech          ← 사본 (우리가 고친 것)
js-super:tech-design          ← 설치된 캐시 (옛 이름)
js-super:merge-back-worktree  ← 사본
js-super:worktree-merge-back  ← 설치된 캐시
```

슬래시 102개, 스킬 61개가 로드됐다. `--setting-sources ""` 가 사용자 설정을 줄이기는 했지만(기본 179 → 102), 설치된 js-super 플러그인 자체는 살아 있다.

### 이것이 뜻하는 것

**작업 중인 사본만 격리해서 검증하려면 `--plugin-dir` 만으로는 부족하다.** 설치된 같은 이름 플러그인이 함께 로드되어 옛 정의가 섞인다.

실제로 이번 실행에서 에이전트가 `Skill` 도구를 두 번 불렀다.

1. `js-super:design-tech` — 새 이름. 커맨드가 잡혀서 "스킬을 부르라" 는 안내를 받음
2. `js-super:tech-design` — 그 안내를 따라 부름. 그런데 이 이름이 캐시의 **옛 커맨드**와 여전히 겹침

즉 이번 세션에서 고친 이름 충돌 수정이 제대로 먹었는지는 **이 방법으로는 확인할 수 없다.** 설치본을 지우거나 다른 이름으로 로드해야 한다.

### 설계에 반영할 것

- 설계서 §4-1 의 `--plugin-dir` 설명에 "같은 이름은 교체됨" 이라고 적었는데, 실측은 그 반대다. 교체되지 않고 공존한다. **정정 필요**
- 발동 층위(2차)에서 "안 불려야 할 때 안 불리는가" 를 검증하려면 이 오염을 먼저 없애야 한다. 안 그러면 캐시의 옛 정의가 발동해도 통과로 보인다
- 해결 후보 세 가지. 어느 쪽인지는 2차 착수 시점에 실측으로 정한다
  1. 사본의 플러그인 이름을 `js-super-eval` 로 바꿔 로드 (이름 충돌 회피)
  2. 임시 설정 디렉토리를 만들어 설치본을 안 보이게 함
  3. 검증 대상 커맨드·스킬만 골라 임시 플러그인으로 재구성

## 5. 부수 관측

- `rate_limit_event` 가 두 실행 모두에서 관측됐다. 설계서 R10(요청 제한으로 병렬 수가 떨어짐)의 감속 신호로 쓸 수 있다.
- `claude_code_version` 이 최상위 키로 나온다. 설계서 R4(출력 형식 변경)의 포맷 카나리에 그대로 쓸 수 있다.
- 이벤트 종류는 `system` / `assistant` / `user` / `rate_limit_event` / `result` 다섯이었다.
- `hook_event`, `hook_id`, `hook_name` 키가 존재한다. 훅 발화 관측이 가능하다.

## 6. 판정

**30분 제약은 여유롭게 지켜진다.** 세그먼트 소요가 예상의 3분의 1이라 계산이 오히려 느슨해졌다.

**보조 에이전트 관측은 가능하다.** 필드가 전부 채워지고 도구 이름만 `Agent` 로 정정하면 된다.

**격리 설계에 구멍이 하나 발견됐다.** `--plugin-dir` 이 설치본을 대체하지 않는다. 1차 범위(Claude 미실행)에는 영향이 없지만, 2차 착수 전에 반드시 풀어야 한다.
