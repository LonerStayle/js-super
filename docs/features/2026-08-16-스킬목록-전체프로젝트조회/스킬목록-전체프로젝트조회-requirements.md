# 요구사항: 스킬목록-전체프로젝트조회

> **다음 단계 안내**: 이 문서는 요구사항 (기획 단계) 입니다. 다음 단계로 `tech-design` skill (또는 `/design-tech` 슬래시) 을 호출해서 `스킬목록-전체프로젝트조회-tech-design.md` (기술 설계서) 를 만드세요. 기술 결정이나 구현 세부사항은 여기 박지 마세요 — 그건 다음 산출물 (tech-design, 3개 트랙이면 plan 까지) 에 들어갑니다.

## 배경

`/list-skills` 는 지금 두 곳만 본다 — 실행한 작업 디렉터리(cwd) 기준 `.claude/skills/` 와 글로벌 `~/.claude/skills/`. 사용자가 여러 프로젝트에서 `/new-skill` 로 skill 을 만들어 왔는데, 어느 프로젝트에 뭘 만들어뒀는지 한 자리에서 볼 방법이 없다. 안 쓰는 skill 을 찾아 정리하고 싶어도 프로젝트를 하나씩 돌며 확인해야 한다.

이 피처는 `/list-skills` 의 조회 범위를 **PC 의 다른 프로젝트까지** 넓힌다. 이는 기존 요구사항 FR-2 ("다른 프로젝트 안 보임", v2.7 new-skill-enhanced) 를 **의도적으로 뒤집는 결정**이다. 따라서 커맨드 본문의 "다른 프로젝트 스캔 금지" 조항과 `CLAUDE.md` 결합 메모의 회귀 표 ("list-skills 다른 프로젝트 스캔 추가 = 회귀") 도 새 규칙에 맞게 함께 갱신해야 한다. 조용히 두면 다음 세션이 이 변경을 회귀로 판정한다.

## 핵심 결정

### 결정 1 — 조회 범위: 다른 프로젝트까지 (갈래 A)

"전체 프로젝트 기준" 의 세 갈래 (A: 다른 프로젝트까지 / B: 저장소 루트 기준 보정 / C: 표식 없는 skill 포함) 중 **A 만 채택**했다.

- B (cwd 가 하위 폴더·워크트리일 때 저장소 루트를 보게 보정) 는 별도 항목으로 다루지 않는다 — 홈 전체 검색이 모든 프로젝트를 어차피 찾아내므로 문제 자체가 흡수된다.
- C (표식 없는 skill 표시) 는 미채택 — 지금처럼 `/new-skill` 이 만든 표식 있는 skill 만 목록에 낸다.

### 결정 2 — 후보 탐색: 홈 전체 검색

"어떤 프로젝트를 뒤질 것인가" 에 세 안이 있었다.

| | 채택 여부 | 이유 |
|---|---|---|
| Claude 기록 기반 (`~/.claude/projects/` 활용) | 버림 | 자동이고 빠르지만, Claude 기록 상태에 의존한다 |
| 수동 등록 목록 | 버림 | 등록 깜빡하면 안 보임 + 목록 관리 부담 |
| **홈 전체 검색** | **채택** | 기록·등록에 의존하지 않고 실제 존재하는 것을 전부 찾는다. 검색 시간이 걸리는 비용은 수용 (사용자 결정) |

홈 디렉터리 아래를 훑어 `.claude/skills/` 디렉터리를 발견하는 방식이다. 무관한 시스템·캐시 폴더 (라이브러리 폴더, 패키지 캐시, 휴지통 등) 는 건너뛴다 — 구체적인 제외 목록과 검색 방법은 기술설계에서 정한다.

### 결정 3 — 다른 프로젝트 skill 삭제: 안내만

목록에서 찾은 다른 프로젝트의 skill 을 지우는 방식으로 두 안 (안내만 / `/remove-skill` 원격 삭제 확장) 중 **안내만**을 채택했다. 삭제는 파일을 건드리는 작업이라 다른 프로젝트를 원격으로 지우는 것은 위험 등급이 한 단계 높고, 목록에 경로가 보이면 그 프로젝트에 가서 `/remove-skill` 한 번이면 된다. `/remove-skill` 본문은 이번 작업에서 변경하지 않는다.

## 요구 항목

**FR-1**: `/list-skills` 는 현재 프로젝트와 글로벌 (`~/.claude/skills/`) 에 더해, 홈 디렉터리 아래 다른 프로젝트들의 `.claude/skills/` 를 찾아 출처 표식 (`.js-super-skill.json`) 이 있는 skill 을 목록에 포함한다.

**FR-2**: 목록은 프로젝트별 그룹으로 묶고, 각 그룹에 그 프로젝트의 절대 경로를 함께 표시한다. 현재 프로젝트와 글로벌은 다른 프로젝트 그룹과 구분되어 보인다.

**FR-3**: 다른 프로젝트 그룹이 하나라도 있으면, 그 skill 을 지우려면 해당 프로젝트로 이동해 `/remove-skill` 을 실행하라는 안내 한 줄을 출력에 포함한다.

**FR-4**: 홈 전체 검색은 무관한 시스템·캐시 폴더를 건너뛴다. 읽기 권한이 없는 폴더는 오류 없이 건너뛴다.

**FR-5**: 기존 조회 규칙은 모든 스코프에 동일하게 적용된다 — 표식 없는 skill 제외, `.removed-<timestamp>` 디렉터리 제외, 읽기 전용 (파일 변경 없음).

**FR-6**: 커맨드 본문의 "다른 프로젝트 스캔 금지" 조항과 `CLAUDE.md` 의 v2.7 결합 메모 (요구사항 FR-2 "다른 프로젝트 안 보임" + 회귀 표) 를 새 규칙 기준으로 갱신한다. 스킬 검증 환경 (`evals/run.py`) 에서 "새로 깨짐" 이 없어야 한다.

## 범위 밖

- **표식 없는 skill 표시** (갈래 C) — 다른 플러그인 / 직접 생성 / 옛 빌더 skill 은 계속 목록에서 제외
- **다른 프로젝트 skill 원격 삭제** — `/remove-skill` 확장 없음, 안내만 (결정 3)
- **skill 재활용 (복사/가져오기) 기능** — 사용 목적 선택에서 제외됨
- **수동 등록 목록 / 중앙 레지스트리** — 홈 전체 검색 채택으로 불필요
- **Claude 기록 (`~/.claude/projects/`) 기반 탐색** — 홈 전체 검색 채택으로 버림
- **저장소 루트 기준 보정 단독 작업** (갈래 B) — 홈 전체 검색이 흡수

## 걸림돌과 제약

- **검색 시간** — 홈 아래 전체를 훑으므로 홈 크기에 비례해 느려질 수 있다. 사용자가 이 비용을 알고 수용했다. 시스템·캐시 폴더 제외로 완화하되, 구체 수치 목표는 두지 않는다.
- **표식은 신뢰 신호일 뿐 보안 경계 아님** — 기존 규약 유지. 표식 파일을 수동 복사하면 비-js-super skill 도 목록에 뜰 수 있다 (낮은 빈도, 수용).
- **빌더는 커맨드로 유지** — `skills/list-skills/` 로 바꾸지 않는다 (자동 발동 사고 방지). 커맨드 이름 ↔ 스킬 디렉터리 이름 충돌 금지 룰도 그대로.
- **버전 bump 금지** — 6 manifest 의 `version` 은 main 에서만 올린다 (워크트리 세션 룰).

## 수용 기준

1. 다른 프로젝트에 `/new-skill` 로 만든 skill 이 있으면, 이 저장소에서 `/list-skills` 실행 시 그 skill 이 프로젝트 경로와 함께 목록에 보인다.
2. 표식 없는 skill 은 어느 스코프에서도 목록에 나오지 않는다.
3. 다른 프로젝트 그룹이 표시될 때 `/remove-skill` 이동 안내가 함께 나온다.
4. `evals/run.py` 실행 시 "새로 깨짐" 이 없다.
