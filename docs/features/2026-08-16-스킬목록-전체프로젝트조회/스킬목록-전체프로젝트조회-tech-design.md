> **다음 단계 안내**: 이 문서는 기술 설계서입니다 (아키텍처 / 컴포넌트 / 데이터 / 인터페이스 / 결정 / 위험 / 테스트 전략). `스킬목록-전체프로젝트조회-requirements.md` 를 기반으로 작성됩니다. 3개 트랙이면 다음 단계 `스킬목록-전체프로젝트조회-implementation-plan.md` (단계별 계획) 의 입력이 됩니다 (`writing-plans` skill 또는 `/write-plan` 슬래시). 2개 확정 트랙 (frontmatter `depth: 2`) 이면 이 문서가 마지막 산출물입니다. 단계별 구현 task 는 여기 박지 마세요 — 그건 다음 산출물 (plan) 에 들어갑니다.

## 1. 아키텍처 개요

`/list-skills` 커맨드는 지시문만 담고, 실제 탐색은 전용 스캔 스크립트가 결정적으로 수행한다. 커맨드가 플러그인 루트 기준 경로로 스크립트를 한 번 실행하면, 스크립트가 홈 전체를 훑어 출처 표식이 있는 skill 을 찾아 세 그룹 (현재 프로젝트 / 글로벌 / 다른 프로젝트들) 으로 분류한 결과를 구조화된 형식으로 돌려준다. 메인 에이전트는 그 결과를 출력 양식에 맞춰 사람이 읽는 목록으로 렌더링만 한다.

스크립트는 파이썬 표준 라이브러리만 사용한다 — 사용자 프로젝트에는 이 저장소의 가상환경이 없으므로, 시스템 파이썬(`python3`)으로 어디서든 돌아야 한다. 스크립트 경로는 플러그인 루트 환경 변수 (`${CLAUDE_PLUGIN_ROOT}`) 로 해석한다 — 훅 설정 (`hooks/hooks.json`) 이 이미 쓰는 선례를 따른다.

스크립트 실행이 실패하면 (변수 미지원 하네스 / 파이썬 부재 등) 커맨드는 기존 두 스코프 조회 (cwd 기준 `.claude/skills` + `~/.claude/skills`, LS 도구 기반) 로 폴백하고 안내 한 줄을 출력한다 — 조회 커맨드가 스크립트 부재로 죽지 않는다.

## 5. 핵심 결정 + 대안 비교

### D1 — 탐색 주체: 전용 스크립트 (사용자 결정)

| | 채택 | 버림 |
|---|---|---|
| 안 | **전용 스캔 스크립트 (`scripts/` 아래)** | 커맨드 본문에 검색 명령 한 줄 인라인 |
| 이유 | 홈 전체 탐색은 프루닝·분류·표식 필터·frontmatter 추출이 얽혀 한 줄로 안 끝난다. 스크립트로 빼면 단위 테스트로 동작을 고정할 수 있다 | 빌더 무스크립트 단순성은 지키지만, 탐색 로직이 지시문 산문에 박혀 검증 불가 |

되돌리는 비용: 낮음 — 커맨드 본문에서 호출 한 줄을 교체하면 된다.

### D2 — 스크립트 위치 해석: 플러그인 루트 변수

사용자 프로젝트에서 실행되므로 cwd 기준 상대 경로나 이 저장소의 가상환경에 의존할 수 없다. `${CLAUDE_PLUGIN_ROOT}` 로 플러그인 설치 위치를 해석해 `python3` 로 직접 실행한다 (표준 라이브러리만 사용, 가상환경 불요). 대안 (cwd 기준 `scripts.` 모듈 import — 기존 skill helper 패턴) 은 js-super 저장소 안에서만 동작해서 버림. 변수 미해석·실행 실패 시 §1 의 폴백 경로.

### D3 — 스캔 범위 규칙

대안 (프루닝 없이 홈 전부 훑기) 은 속도와 OS 보호 폴더 접근 문제로 버렸다. 채택한 규칙:

- 홈 디렉터리 아래를 위에서부터 내려가며 탐색하되, **숨김 디렉터리는 내려가지 않는다**. 단 `.claude` 디렉터리 자체는 프루닝 전에 매치한다 (숨김이지만 찾는 대상).
- 무거운 폴더는 이름으로 프루닝: `Library`, `node_modules`, `.git`, 휴지통, 패키지·브라우저 캐시 류 (정확한 목록은 스크립트 상수로, 구현 단계에서 확정).
- 심볼릭 링크는 따라가지 않는다 (루프 방지).
- 접근 권한 오류는 무시하고 계속 진행한다 (FR-4).
- **현재 프로젝트 판별 (상향 탐지)**: cwd 에서 위로 올라가며 `.claude/skills` 를 가진 첫 디렉터리를 현재 프로젝트 루트로 잡는다. **홈 디렉터리 자체는 후보에서 제외한다** — 홈의 `.claude/skills` 는 글로벌 스코프다. 홈 (또는 파일시스템 루트) 에 도달할 때까지 매치가 없으면 현재 프로젝트 그룹은 빈 그룹 ("없음") 이다. 이 상향 탐지가 요구사항의 "갈래 B 흡수" (하위 폴더·워크트리에서 실행해도 올바른 프로젝트 인식) 를 구현한다.
- **그룹 채우기 방식**: 현재 프로젝트 그룹과 글로벌 그룹은 각자의 루트를 **직접 열거**해 채운다 (홈 스캔 결과에서 골라내는 방식이 아님). 따라서 현재 프로젝트가 숨김 경로 (워크트리 등) 아래거나 홈 밖이어도 현재 그룹에는 나온다. "다른 프로젝트들" 그룹 = 홈 스캔 결과에서 현재 프로젝트 루트와 글로벌을 뺀 나머지.
- 숨김 폴더 아래에 있는 **다른** 프로젝트는 목록에서 빠진다 — 수용 (워크트리 디렉터리 (`.worktrees/`) 아래 사본이 중복으로 잡히는 것을 막는 효과가 더 크다). 현재 프로젝트는 직접 열거라 이 제한의 예외다.

### D4 — 출력 계약: 스크립트는 JSON, 렌더는 커맨드

스크립트는 그룹별 skill 배열 (슬러그 / 경로 / 설명 1줄 / 생성 시각) 을 JSON 으로만 출력하고, 사람이 읽는 목록 형식은 커맨드 지시문이 정한다. 대안 (스크립트가 최종 목록 텍스트까지 출력) 은 출력 양식을 바꿀 때마다 스크립트를 고쳐야 해서 버림. 설명 1줄은 각 skill 의 `SKILL.md` frontmatter 에서 스크립트가 추출하고, 실패 시 "(설명 없음)" 폴백 (기존 규칙 유지). 생성 시각은 출처 표식 파일의 `created` 값에서만 읽고, 값이 없거나 못 읽으면 표시를 생략한다 — 파일시스템 시각은 쓰지 않는다 (복사·클론된 skill 에서 값이 갈리므로).

### D5 — 실패 폴백: 기존 두 스코프 조회

스크립트 실행이 어떤 이유로든 실패하면 커맨드는 오류로 멈추지 않고, 기존 방식 (cwd `.claude/skills` + `~/.claude/skills`, LS 도구) 으로 조회한 뒤 "홈 전체 스캔을 사용할 수 없어 두 스코프만 조회했다" 안내를 붙인다. 대안 (실패 시 중단) 은 조회 커맨드의 가용성을 스크립트에 인질로 잡혀서 버림.

## 7. 테스트 전략

- **단위 테스트** (신규 테스트 파일 — §2 표의 경로, 기존 helper 테스트 패턴 답습): 임시 디렉터리에 가짜 홈 구조를 만들어 검증 —
  1. 표식 있는 skill 만 통과 (표식 없는 디렉터리 제외)
  2. `.removed-<timestamp>` 디렉터리 제외
  3. 숨김·무거운 폴더 프루닝 (그 아래 skill 이 안 잡힘)
  4. 세 그룹 분류 — 현재 프로젝트 / 글로벌 / 다른 프로젝트 (현재·글로벌이 다른 프로젝트 그룹에 중복으로 안 들어감)
  5. cwd 가 프로젝트 하위 폴더일 때 상향 탐지로 올바른 프로젝트 루트 인식
  6. 설명 추출 실패 시 "(설명 없음)" 폴백
  7. 접근 권한 오류 디렉터리 무시 (오류로 죽지 않음)
- **회귀**: `.venv/bin/python evals/run.py` — 결합 룰 "새로 깨짐" 0 (FR-6 수용 기준). 신규 결합 메모의 확인용 명령도 같은 실행에서 검사된다.
- **E2E 수동 시나리오**: scratchpad 에 가짜 홈 구조를 만들어 스크립트 단독 실행으로 JSON 을 확인하고, 실제 홈에서 1회 실행한다. 통과 기준 — 오류 없이 완주하고 유효한 JSON 을 반환할 것. 소요 시간은 참고로 함께 보고한다 (판정 기준 아님 — 검색 시간은 요구사항에서 수용됨). 산출물은 저장소에 커밋하지 않는다.
