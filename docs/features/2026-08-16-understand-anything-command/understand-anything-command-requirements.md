# 요구사항: understand-anything-command

## 배경

Understand-Anything 은 코드베이스를 분석해 대화형 지식 그래프로 만들어 주는 독립 플러그인이다. 구조 추출은 결정론 스크립트(구문 분석 기반)가 맡고, 요약·아키텍처 해석 같은 의미 부여는 LLM 이 맡는 하이브리드 구조다. 이 기능을 js-super 안에서 쓰고 싶은데, 스킬로 넣으면 스킬 설명이 매 세션 컨텍스트에 상주해 부담이 크다. 그래서 **명시 호출 전용 커맨드**(호출할 때만 본문이 로드됨)로 이식한다.

원본은 슬래시 명령 9개 규모다. 이번 이식은 그중 핵심만 추려서 가져오고, 무거운 부속(프런트엔드 빌드, 특수 그래프 3종)은 제외한다.

## 핵심 결정

대화에서 정한 방향과, 버린 대안·이유를 남긴다.

**1. 이식 범위 — 메인 파이프라인 + 조회형 4종.**
그래프 생성(understand)과 그래프를 읽는 조회형 4종(chat / diff / explain / onboard)을 가져온다. 조회형은 스크립트 의존이 없는 순수 프롬프트라 이식 비용이 거의 없다. "메인만" 안은 만들어 놓고 활용 수단이 빈약해져서, "9개 전부" 안은 프런트엔드 빌드 파이프라인까지 끌려와서 버렸다.

**2. 결정론 엔진 확보 — 실행 시 원본 내려받기.**
분석 엔진(원본의 core 패키지와 구문 분석 문법 파일들)은 js-super 저장소에 넣지 않는다. 최초 실행 때 원저장소를 **버전 고정**으로 사용자 머신에 내려받아 한 번 준비해 두고 재사용한다. "저장소에 번들" 안은 수십 MB 바이너리 커밋과 업데이트 부담 때문에, "LLM 대체" 안은 원본 프로젝트가 이미 시도했다가 토큰 비용·정확도 문제로 되돌아온 길이라 버렸다.

**3. 그래프 확인 수단 — 원본 릴리즈의 viewer 재활용.**
원저장소가 릴리즈마다 빌드 완료된 단독 viewer 를 배포한다. 이걸 버전 고정으로 받아 띄우면 빌드 없이 대시보드 수준의 화면을 얻는다. 깨지는 조건: 원저장소 릴리즈가 사라지면 못 쓴다 — 그때는 HTML 리포트 생성으로 대체한다(차선안으로 기록).

**4. 커맨드 구성 — 5개 1:1.**
원본 기능과 같은 이름 체계로 커맨드 5개를 노출한다. 인자 해석이 단순하고 원본 사용감과 같다. "조회 통합 1개" 안은 인자 사용감이 한 겹 복잡해져서 버렸다.

**5. 워크트리 정책 — 메인 루트 저장 + 옵트아웃.**
워크트리 안에서 실행해도 산출물은 기본적으로 메인 저장소 루트에 저장한다(워크트리 소멸에도 그래프 보존, 재분석 비용 절약). 플래그를 주면 현재 위치에 저장할 수 있다. "항상 현재 위치" 안은 워크트리 삭제와 함께 그래프가 사라지는 문제로, "매번 질문" 안은 실행 마찰 때문에 버렸다.

**6. 훅 기반 자동 업데이트 — 제외.**
커밋할 때마다 그래프 갱신을 유도하는 상시 훅은 가져오지 않는다. js-super 를 가볍게 유지하려는 이번 이식의 취지와 충돌한다. 대신 understand 커맨드를 다시 실행하면 변경분만 증분 분석하는 경로는 유지한다.

## 제공 기능

| 커맨드 | 역할 |
|---|---|
| `/understand` | 대상 프로젝트를 분석해 지식 그래프 생성 (재실행 시 변경분만 증분 분석) |
| `/understand-chat` | 그래프 기반 코드베이스 질의응답 |
| `/understand-diff` | 현재 변경분의 영향 범위 분석 |
| `/understand-explain` | 특정 파일·함수 딥다이브 설명 |
| `/understand-onboard` | 온보딩 가이드 문서 생성 |

## 요구 항목

**FR-1**: js-super 는 `/understand` 커맨드를 제공한다 — 대상 프로젝트를 분석해 지식 그래프 산출물을 생성하고, 이미 그래프가 있으면 변경분만 증분 분석한다.

**FR-2**: 조회형 커맨드 4종(`/understand-chat`, `/understand-diff`, `/understand-explain`, `/understand-onboard`)을 제공한다 — 생성된 그래프를 읽어 각각 질의응답, 변경 영향 분석, 파일 딥다이브, 온보딩 문서 생성을 수행한다.

**FR-3**: 5개 커맨드 모두 `disable-model-invocation: true` — 명시 슬래시 호출 전용이며 자동 발동 경로가 없다.

**FR-4**: 결정론 분석 엔진은 최초 실행 시 원저장소(버전 고정)를 사용자 머신에 내려받아 준비하고 이후 재사용한다. js-super 저장소에는 엔진 코드·바이너리를 포함하지 않는다.

**FR-5**: 그래프 확인은 원본 릴리즈의 완성 viewer 를 버전 고정으로 재활용한다. 이를 위해 그래프 산출물의 형식은 고정한 원본 버전과 호환을 유지한다.

**FR-6**: 워크트리 안에서 실행하면 산출물을 기본적으로 메인 저장소 루트에 저장하고, 플래그로 현재 위치 저장을 선택할 수 있다.

**FR-7**: 사용자에게 확인이 필요한 지점(분석 제외 목록 확인, 대규모 프로젝트 범위 조정 등)은 js-super 의 사용자 질문 규약(AskUserQuestion 도구)을 따른다.

**FR-8**: 전체 분석 전에 프로젝트 규모(파일 수)를 보고하고, 대규모 프로젝트면 범위 축소를 제안한다 — 사용자가 토큰 비용을 예상할 수 있게 한다.

**FR-9**: 사용자에게 보이는 안내문은 js-super 한국어 친화 톤을 따른다. 그래프 내용(요약·레이어명)의 언어는 원본의 언어 자동 감지 동작을 유지한다.

## 범위 밖

- 대시보드 자체 이식 (React 프런트엔드와 그 빌드 파이프라인) — 원본 viewer 재활용으로 대체
- 특수 그래프 3종: `/understand-domain`, `/understand-knowledge`, `/understand-figma`
- 훅 기반 자동 업데이트 (커밋 감지 상시 훅)
- 엔진을 js-super 저장소에 번들하는 방식
- 원본의 미사용 코드(플러그인 내 TS 소스 711줄), 홈페이지, 타 플랫폼 설치 스크립트
- 원본 플러그인과의 동시 설치 지원 — 커맨드 이름이 겹치므로 동시 설치는 전제하지 않는다

## 수용 기준

1. 원본 플러그인이 설치되지 않은 머신에서, js-super 만으로 `/understand` 가 지식 그래프를 생성한다.
2. 조회형 4종이 그 그래프를 읽어 동작한다.
3. 원본 릴리즈의 viewer(버전 고정)로 그래프가 열린다 — 산출물 형식이 원본과 호환된다.
4. js-super 저장소에 빌드 파이프라인·대용량 바이너리가 추가되지 않는다.
5. 커맨드 5개 모두 명시 호출 전용이다 — 자동 발동 경로 0.

## 제약과 걸림돌

- 사용자 머신 요구: Node.js 22 이상, pnpm 10 이상, Python 3, git. 이 중 하나라도 없으면 엔진 준비 단계에서 안내 후 중단해야 한다.
- 최초 실행 1회는 네트워크가 필요하다 (엔진 내려받기). viewer 를 처음 띄울 때도 필요하다.
- 원저장소 릴리즈 의존 — 버전 고정으로 완화하되, 릴리즈 소실 시 viewer 대체 수단(HTML 리포트)이 차선이다.
- 전체 분석은 대상 프로젝트 크기에 비례해 토큰을 소모한다. FR-8 의 규모 보고가 완충 장치다.
