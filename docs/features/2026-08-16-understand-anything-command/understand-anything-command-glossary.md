# 용어집: understand-anything-command

> 이 문서는 `understand-anything-command-implementation-plan.md` 를 처음 읽는 사람을 위한 참고 자료입니다.
> 계획서가 바뀌면 다시 만들어지며, 내용이 어긋날 때는 계획서가 정본입니다.

## 한눈에 보기

이 피처는 js-super 저장소의 commands 폴더 아래에 새 슬래시 명령 다섯 개(understand, understand-chat, understand-diff, understand-explain, understand-onboard)를 추가한다. 실제 코드 분석 엔진은 js-super 저장소 안에 없다. 최초 실행 시 별도의 외부 오픈소스 저장소(Understand-Anything)를 사용자 홈 디렉토리에 통째로 내려받고, 그 안에 있는 원본 절차를 그대로 따르는 구조다. 읽기는 commands/understand.md 부터 시작하면 되고, 그 문서가 참조하는 원본 절차는 로컬에 이미 존재하는 원저장소 사본(/Users/seobi/jinsup_space/Understand-Anything)에서 실제로 확인할 수 있다. 나머지 조회용 커맨드 네 개는 원본 절차를 그대로 옮겨 담은 것이라, 원저장소의 같은 이름 문서와 내용이 거의 동일하다.

## 이번에 새로 만드는 것

| 이름 | 종류 | 위치 | 하는 일 |
|---|---|---|---|
| `ENGINE_HOME` | bash 변수 | `commands/understand.md` | 원저장소 전체를 내려받아 담아두는 고정 경로를 가리킨다. 사용자 홈 아래 점 파일 형태의 폴더이고, 최초 실행 때 이 경로로 저장소를 통째로 clone 한다. |
| `PLUGIN_ROOT` | bash 변수 | `commands/understand.md` | 실제 분석 엔진(절차 문서, 보조 에이전트 프롬프트, 빌드된 패키지)이 들어 있는 경로. ENGINE_HOME 바로 밑의 하위 폴더 하나를 가리키도록 고정값으로 정의한다. 원저장소 자체가 저장소 루트와 실제 플러그인 폴더로 한 겹 중첩된 구조라 이렇게 정의된다(아래 헷갈리는 짝 참고). |

## 헷갈리기 쉬운 짝

| 이것 | 저것 | 차이 |
|---|---|---|
| ENGINE_HOME (원저장소를 내려받는 바깥 폴더) | PLUGIN_ROOT (그 안의 실제 플러그인 폴더) | 두 이름이 가리키는 경로가 한 겹 중첩돼 있다. ENGINE_HOME 은 원저장소 전체를 clone 받는 바깥 폴더이고, 실제 절차 문서와 에이전트 프롬프트와 패키지는 그 밑의 하위 폴더 안에 들어 있다. 실제로 로컬 사본을 열어보니 저장소 루트에는 README나 문서 파일들이 있고, 그 아래 별도 하위 폴더 안에 진짜 플러그인 내용물이 있는 구조였다. js-super 는 이 구조를 고정 경로 두 줄로 반영한 것이다. |
| commands/understand.md (js-super, 새로 생김) | skills/understand/SKILL.md (원저장소, 이미 있음) | 둘 다 같은 분석 절차를 다루지만 위치와 역할이 다르다. 앞은 js-super 저장소에 새로 생기는 얇은 진입점으로, 부트스트랩 절차와 몇 가지 덮어쓰기 조항만 담는다. 뒤는 실제 준비부터 저장까지 전체 절차가 담긴 원본 문서로, js-super 코드에는 내용이 들어 있지 않고 실행할 때 읽어서 따르기만 한다. |
| PLUGIN_ROOT (js-super 이식판의 정의) | PLUGIN_ROOT (원저장소 원본의 정의) | 이름이 완전히 같은 변수인데 정해지는 방식이 다르다. 원저장소 쪽은 여러 후보 경로를 순서대로 확인해 처음 존재하는 곳을 고르는 방식이고, js-super 이식판은 이 탐색을 생략하고 경로 하나로 고정한다. 계획서 자신도 이 차이를 덮어쓰기 조항으로 명시하고 있다. |
| .ua/ (새 프로젝트) | .understand-anything/ (기존 프로젝트, 예전 이름) | 같은 데이터 디렉토리를 가리키는 두 이름이다. 이미 예전 이름으로 분석한 적 있는 프로젝트는 그 이름을 계속 쓰고, 처음 분석하는 프로젝트는 새 이름을 쓴다. 매 실행마다 어느 쪽이 이미 존재하는지 확인해서 고르므로 두 폴더가 동시에 쓰이지는 않는다. |
