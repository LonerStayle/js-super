# js-super 프롬프트 혼동성 전체 검토 리포트

## 검토 개요

- **검토 파일 수**: 65개 (커맨드 프롬프트 + skill 본문 + 서브에이전트 프롬프트 템플릿)
- **총 발견 수**: 188건
- **심각도 분포**: high 31건 / medium 97건 / low 60건
- **발견 없음**: 4개 파일 (`commands/tech-design.md`, `commands/worktree-merge-back.md`, `commands/write-plan.md`, `skills/test-driven-development/SKILL.md`)
- **검토일**: 2026-07-18

검토는 각 프롬프트를 "이 텍스트만 읽고 실행하는 LLM 이 세션마다 다르게 행동할 여지가 있는가"라는 기준으로 봤습니다. 즉 문법 오류가 아니라 **지시의 모순·모호·버전 잔재·잘못된 참조**를 찾았습니다. 대부분의 발견은 새로운 것을 만들어내는 결함이 아니라, 규칙이 개정됐는데 문서의 다른 부분이 함께 갱신되지 않아 생긴 **내부 불일치(version-drift·contradiction)** 입니다. 실제 오작동 가능성이 낮은 표기 수준 지적(dot 다이어그램 고아 노드 등)은 low 로 냉정하게 분류했습니다.

## 핵심 요약

가장 시급한 문제를 우선순위 순으로 정리합니다.

### 1. generating-html v2.2.1 전환 잔재 (최대 blast radius)

`generating-html` 은 v2.2.1 에서 "원본 `.md` 를 format-only 로 다시 써서 prettified 버전을 만들고 동기적으로 사용자에게 보여준다"는 흐름(구 Subagent A)을 **제거**하고, "백그라운드로 사람 전용 `.html` 사본만 만들고 메인은 결과를 기다리지 않는다"로 바뀌었습니다. 그런데 아래 파일들이 아직 옛 "prettified `.md`" 동기 흐름을 지시합니다.

- **영향 파일**: `skills/generating-html/SKILL.md`(high 2건 포함), `skills/brainstorming/SKILL.md`, `skills/tech-design/SKILL.md`, `skills/writing-plans/SKILL.md`, `skills/generating-html/html-companion-prompt.md`
- **위험**: LLM 이 존재하지 않는 prettified 결과를 동기 대기하거나, 사람 전용 `.html` 을 직접 읽어 의미 drift 를 유발하거나, RAW `.md` 를 "정제 완료"로 잘못 보고할 수 있습니다.
- **권장 조치**: 4개 skill 의 "format-only pass / PRETTIFIED / 승인" 서술을 v2.2.1+ 실제 동작(백그라운드 `.html` 사본, 메인 비대기, 사용자에겐 RAW `.md`)에 맞춰 일괄 갱신. `generating-html/SKILL.md` 안의 죽은 Subagent Prompt Template·Process Flow·Sanity-Check·Acceptance 섹션을 삭제하거나 DEPRECATED 표시.

### 2. auto-* 4종 + executing-plans 의 frontmatter/Anti-Patterns 자기모순

auto-brainstorming/auto-tech-design/auto-writing-plans 의 frontmatter 는 "AskUserQuestion / generating-html 호출 X" 라고 못박는데, 본문 Step 4.5/4.6 은 generating-html 을 백그라운드 호출하라고 지시합니다. auto-executing-plans 는 Entry Guard 실패 시 AskUserQuestion 게이트를 써야 하는데 Anti-Patterns 는 "AskUserQuestion NEVER" 라고 합니다. executing-plans 의 `--no-ask` 섹션은 brainstorming 계열 boilerplate 를 복붙해 "이 skill 엔 AskUserQuestion 호출이 없다"고 잘못 주장합니다.

- **영향 파일**: `skills/auto-brainstorming/SKILL.md`, `skills/auto-tech-design/SKILL.md`, `skills/auto-writing-plans/SKILL.md`, `skills/auto-executing-plans/SKILL.md`, `skills/executing-plans/SKILL.md`, `commands/auto-brainstorm.md`, `commands/auto-tech-design.md`
- **위험**: 도구 팝업을 띄울지 prose 로 물을지, Step 4.5/4.6 을 실행할지 건너뛸지 세션마다 갈립니다.
- **권장 조치**: frontmatter description 을 v2.3.2+/v2.0.3+ 실제 상태로 갱신("generating-html 은 Step 4.x 에서 백그라운드 호출", AskUserQuestion 관련 범위 명확화). 커맨드의 `--no-ask` 설명도 각 skill 의 실제 동작과 맞춤.

### 3. change-history ↔ executing-plans 변경이력 배칭 모순

`change-history/SKILL.md` 앞부분은 "executing-plans 는 task 마다 즉시 1개 entry 를 쓴다(default form)"고 하고, 뒷부분(End-of-Run 섹션·Anti-Patterns)은 "git-fast(commit_policy: per-task) 모드에서는 전체 실행이 끝난 뒤 단 1개만 쓴다"고 정반대로 말합니다. `commit_policy: per-task` 라는 이름이 "task 당 entry"를 연상시키는 네이밍 충돌까지 겹칩니다. `executing-plans/SKILL.md` 도 HARD-GATE·dot 다이어그램·frontmatter·Anti-Patterns 가 서로 다른 commit 단위를 지시합니다.

- **영향 파일**: `skills/change-history/SKILL.md`(high), `skills/executing-plans/SKILL.md`(high 2건), `commands/execute-plan.md`(description)
- **위험**: task 완료마다 미리 entry 를 append 해 감사 추적이 중복/누락되고, 매 task 마다 plan.md 를 건드려 `git diff HEAD` 오염을 스스로 유발합니다.
- **권장 조치**: "Code-Change Entry" 섹션 최상단에 commit_policy 분기 규칙을 먼저 명시하고, 네이밍 충돌을 한 줄로 해소.

### 4. 존재하지 않는 `superpowers:` 네임스페이스 참조 (js-super 자체 skill 한정)

이 플러그인은 `js-super:` 네임스페이스로 skill 을 노출합니다. 그런데 몇몇 **js-super 자체 skill**(upstream mirror 아님)이 upstream 시절 `superpowers:` 접두어를 그대로 남겨, Skill 도구를 문자 그대로 호출하면 실패할 수 있습니다.

- **영향 파일(포크에서 고쳐야 함)**: `skills/requesting-code-review/SKILL.md`(high, `superpowers:code-reviewer`), `skills/subagent-driven-development/SKILL.md`(medium), `skills/systematic-debugging/SKILL.md`(medium, `superpowers:test-driven-development`/`verification-before-completion`)
- **참고**: og-*·writing-skills·using-git-worktrees 등 동일 문제는 upstream mirror 라 별도 섹션에서 다룹니다.
- **권장 조치**: 위 3개 파일의 `superpowers:` 접두어를 `js-super:` 로 교체(또는 서브에이전트는 `general-purpose` + 템플릿 조합으로 통일).

### 5. feature 폴더 경로 slug 불일치

`find_latest_slug` 는 폴더명 `YYYY-MM-DD-<slug>` 에서 날짜를 뗀 slug 만 반환하는데, 여러 파일의 경로 템플릿이 `docs/features/<slug>/` 로 날짜 접두어를 빠뜨려, 문자 그대로 따르면 실제 폴더를 못 찾습니다.

- **영향 파일**: `commands/pretty-md.md`(high), `commands/sync-html.md`(medium), `skills/api-auto-testing/SKILL.md`(medium, `docs/features/<...>/` 축약)
- **권장 조치**: 경로를 `docs/features/YYYY-MM-DD-<slug>/` 로 명시하거나 glob 매칭임을 표기. 여러 파일 공통이라 함께 patch.

### 6. worktree env 파일 처리 안전성

`setting-up-worktrees` 는 Step 2 헤더/HARD-GATE 는 "절대 묻지 말고 자동 복사"라는데 본문 실행 문구는 "추가/제외 알려주세요 + 사용자 응답 catch"로 응답 대기처럼 읽힙니다. `worktree-merge-back` Step 4.5 는 `git status --porcelain` 으로 env 후보를 찾는데, 이 명령은 gitignored 파일을 기본 제외하므로 `.env.local` 같은 실제 대상이 **항상 비어** "동기화할 파일 없음"으로 오판합니다.

- **영향 파일**: `skills/setting-up-worktrees/SKILL.md`(high), `skills/worktree-merge-back/SKILL.md`(high, 깨진 bash 예시), `commands/worktree.md`(medium)
- **위험**: 블로킹 여부가 갈리고, env 동기화 기능이 조용히 무효화되어 v2.5.1 이 해결하려던 stale env 문제를 재현합니다.
- **권장 조치**: 통지문/응답대기 여부를 명시하고, `--ignored=matching` 또는 `find` 기반 스캔으로 교체.

### 7. js-super-sub-driven Implementer 모델 결정 모순

`js-super-sub-driven/SKILL.md` 는 최소 5곳에서 "Implementer 모델을 plan 의 `**Model**:` 필드에서 읽어라(기본 sonnet)"라고 하는데, W-2(v2.0.0+) Stage 1 섹션은 "Implementer 는 haiku 고정, Model 필드 무시"라고 선언합니다. 동일 디렉토리의 `spec-reviewer-prompt.md` 헤더 주석도 "trivial task 면 haiku 로 낮춰도 된다"고 해 SKILL.md 의 "spec reviewer 는 항상 sonnet 고정(D11)"과 충돌합니다.

- **영향 파일**: `skills/js-super-sub-driven/SKILL.md`(high), `skills/js-super-sub-driven/spec-reviewer-prompt.md`(high)
- **위험**: 실제 dispatch 모델이 세션마다 달라지고, 설계 결정(D11)을 무단 위반합니다.
- **권장 조치**: v2.0.0+ 를 단일 진실로 삼아 dispatch 예시·Example Workflow·룰2 표·Anti-Patterns·reviewer 헤더 주석을 모두 "Implementer=haiku 고정, spec reviewer=sonnet 고정"으로 통일.
