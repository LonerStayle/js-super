# 스킬 검증 환경 사용법

js-super 의 스킬과 커맨드가 의도대로 동작하는지 확인하는 도구입니다. 저장소를 개발하는 쪽만 씁니다. 플러그인 사용자에게는 로드되지 않습니다.

설계 문서는 `docs/features/2026-08-15-skill-eval-harness/` 에 있습니다.

---

## 처음 한 번만

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

`.venv/` 는 gitignore 대상이라 커밋되지 않습니다. 워크트리마다 한 번씩 만들면 됩니다.

## 매번 쓰는 명령

```bash
.venv/bin/python evals/run.py
```

이게 전부입니다. 3초 정도 걸립니다. 스킬 본문을 고친 뒤에 이 한 줄을 돌리면 됩니다.

| 종료 코드 | 뜻 |
|---|---|
| 0 | 새로 깨진 것이 없음 |
| 1 | 새로 깨진 것이나 분류 안 된 항목이 있음 |
| 2 | 검사 단계에서 막힘 (상충하는 기대값이나 케이스 형식 오류) |
| 3 | `--accept` 했는데 분류 안 된 항목이 있어 거부됨 |

옵션은 두 개뿐입니다.

```bash
.venv/bin/python evals/run.py --quiet    # 요약 한 줄만
.venv/bin/python evals/run.py --accept   # 지금 결과를 정답으로 굳힘
```

## 결과 읽는 법

```
검증 결과 — 117건, 3.0초

  통과                 62
  이미 알려진 실패           3
  판정 대기              46
  실행 못 함              6
```

| 표시 | 뜻 | 할 일 |
|---|---|---|
| 통과 | 정상 | 없음 |
| 새로 깨짐 | 이전엔 통과했는데 이번에 실패 | **고쳐야 합니다** |
| 실패 | 실패인데 아직 분류 안 됨 | 회귀인지 낡음인지 정해야 합니다 |
| 신규 | 기준선에 없는 항목 | 분류해야 합니다 |
| 고쳐짐 | 실패하던 게 통과로 바뀜 | `--accept` 로 굳히세요 |
| 이미 알려진 실패 | 낡았다고 표시해둔 것 | 없음 |
| 판정 대기 | 자연어 기대값이라 기계가 판정 못 함 | 2차에서 모델 판정이 붙습니다 |
| 실행 못 함 | 자리표시자가 들어 그대로 실행 불가 | 2차에서 실제 경로로 바꿉니다 |

**"새로 깨짐" 만 보면 됩니다.** 나머지는 이미 알고 있는 상태입니다.

## 스킬을 고친 뒤 흐름

1. 스킬 본문을 수정합니다
2. `.venv/bin/python evals/run.py` 를 돌립니다
3. "새로 깨짐" 이 없으면 그대로 커밋합니다
4. 있으면 고칩니다. 고치는 게 맞고 옛 기대값이 낡은 거라면 `evals/labels.json` 에 낡음으로 적고 `--accept` 합니다

## 무엇을 검사하나

**결합 룰 136건** — `CLAUDE.md` 와 fixture README 의 bash 코드 블록을 실행 시점에 직접 읽어 돌립니다. 룰을 따로 복제하지 않으므로 `CLAUDE.md` 를 고치면 그 즉시 반영됩니다.

**기존 pytest** — `scripts/tests` 63함수 + `evals/tests` 116함수를 항상 전수로 돌립니다.

**정적 케이스 2건** — eval 자산이 사용자 로드 경로에 없는지, 커맨드 이름이 스킬 이름을 가리지 않는지 봅니다.

지금은 실제로 Claude 를 띄우지 않습니다. 그래서 3초에 끝나고 비용이 들지 않습니다.

## 새 케이스 추가하기

`evals/cases/` 아래에 마크다운 파일을 만듭니다. 앞머리에 메타데이터를 얹고 그 아래는 사람이 읽는 시나리오 설명입니다.

```markdown
---
id: self/무엇을-검사하나
title: 한 줄 제목
status: active            # active | stale | wip | blocked
layer: [C]                # A 발동 / B 절차 / C 산출물 / D 결합
covers:
  - skills/*/SKILL.md     # 이 케이스가 커버하는 대상 (미등록 목록 계산에 씀)
expect:
  - kind: shell
    argv: ["bash", "-c", "find commands -mindepth 1 -type d | wc -l"]
    op: eq
    value: 0
---

# 사람이 읽는 시나리오

무엇을 왜 검사하는지, 과거에 어떤 사고가 있었는지, 이 검사가 놓치는 게 무엇인지 적습니다.
```

비교 연산은 `eq`, `gte`, `lte`, `zero`, `lines_eq`, `lines_gte`, `exists`, `capture` 입니다.

추가한 뒤 `--accept` 로 기준선에 넣으면 다음부터 회귀 판정 대상이 됩니다.

## `CLAUDE.md` 에 결합 룰 추가하기

기존 형식 그대로 쓰면 자동으로 잡힙니다.

````markdown
```bash
grep -c "무언가" skills/x/SKILL.md
# expected: 1
```
````

지켜야 할 것 세 가지입니다.

- 코드 펜스 언어가 `bash` / `sh` / `shell` 이어야 합니다
- 명령이 읽기 전용이어야 합니다. 파일을 고치거나 지우는 명령은 관문에 막혀 실행되지 않습니다
- 기대값이 순수 숫자면 기계가 판정합니다. `0 (Anti-Pattern catch 라인만 허용)` 처럼 조건이 붙으면 판정 대기로 남습니다

## 지금 안 되는 것

- 스킬이 실제로 발동하는지는 안 봅니다 (2차)
- 승인 게이트를 제대로 띄우는지도 안 봅니다 (2차, 게다가 헤드리스 실행에서 `AskUserQuestion` 이 발화하지 않아 근사만 가능)
- 기존 fixture 44건이 아직 케이스로 안 옮겨졌습니다 (2차)
- 영향 범위만 골라 돌리는 기능이 아직 없습니다. 지금은 늘 전부 돌리는데 3초라 문제가 안 됩니다 (2차)

미등록 대상이 수십 건 뜨는 건 정상입니다. 케이스가 아직 2건뿐이라서입니다.

## 기존 bash 스위트 상태 (2026-08-15 전수 실행)

`tests/` 아래에는 upstream 에서 상속한 bash 테스트가 있습니다. 전부 돌려본 결과입니다.

| 스위트 | 결과 | 비고 |
|---|---|---|
| `tests/codex-plugin-sync` | 16건 통과 | 순수 bash, 무료 |
| `tests/opencode` | 1건 통과 | 통합은 OpenCode 설치 필요 |
| `tests/brainstorm-server` | 56건 통과 | `npm install` 후 node 실행 |
| `tests/skill-triggering` | 6건 통과 | 실제 Claude 호출, `--plugin-dir` 로 워크트리 로드 |
| `tests/explicit-skill-requests` | 4건 통과 | 프롬프트 9개 중 4개만 러너에 걸려 있음 |
| `tests/claude-code` | **통과 불가** | 아래 참조 |
| `tests/subagent-driven-dev` | 미실행 | 앱을 처음부터 만드는 시나리오, 하나에 10~30분 |

### `tests/claude-code` 가 통과할 수 없는 이유

두 가지가 겹칩니다.

**첫째, 타임아웃이 실제 응답 시간보다 짧았습니다.** 30초로 박혀 있는데 실제 응답은 37초 걸립니다. 첫 호출에서 잘려 `Execution error` 만 나왔습니다. 2026-08-15 에 120초로 올렸습니다.

**둘째, 이게 근본 원인인데, 영어 응답을 전제로 짜였습니다.** 단언 15개가 `read.*plan`, `spec.*compliance`, `self-review` 같은 영어 문구를 grep 합니다. 그런데 이 환경의 에이전트는 한국어로 답합니다. 내용이 정확해도 "메인이 plan 파일을 한 번 읽고 ... 추출한 뒤" 는 `read.*plan` 에 안 걸립니다.

즉 스킬이 옳게 동작해도 실패합니다. **판정 로직이 자연어 표면에 묶여 있어서 생기는 문제**이고, 이 검증 환경이 그 방식을 안 쓰는 이유이기도 합니다. 도구 호출 기록처럼 언어와 무관한 신호를 봐야 합니다.

`tests/claude-code` 의 판정 로직은 2차에서 폐기 대상입니다. 프롬프트 자산은 이관 대상입니다.

## 2차 착수 전에 반드시 풀어야 할 것

`--plugin-dir` 이 설치된 같은 이름 플러그인을 **대체하지 않습니다.** 사본을 로드해도 설치본이 같이 살아 있어서 옛 정의가 섞입니다. 발동 검사를 붙이기 전에 이걸 먼저 해결해야 합니다. 안 그러면 캐시의 옛 정의가 발동해도 통과로 보입니다.

근거는 `docs/features/2026-08-15-skill-eval-harness/사전실측-노트.md` §4 에 있습니다.
